# Test protocol

A usability test is a procedure. Written down, piloted, and followed the same
way with every participant, it produces sessions that can be compared.

| #   | Check                                                                                            | How                                                                 | Source                                                      |
| --- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- | ----------------------------------------------------------- |
| TP1 | Every task is a realistic goal a participant would have                                          | read each task; an invented errand with no motive is a finding      | McCloskey, _Turn User Goals into Task Scenarios_, NN/g 2014 |
| TP2 | Tasks ask the participant to act, not to describe what they would do                             | look for "tell me how you would"                                    | McCloskey, NN/g 2014                                        |
| TP3 | Tasks contain no interface labels and no steps                                                   | compare task wording with the screen's labels                       | McCloskey, NN/g 2014                                        |
| TP4 | Success, partial success, failure and a time limit are defined per task before the first session | the criteria carry a date earlier than session 1                    | ISO 9241-11:2018 (effectiveness)                            |
| TP5 | Effectiveness, efficiency and satisfaction are each measured                                     | the data sheet has task success, time or steps, and a questionnaire | ISO 9241-11:2018                                            |
| TP6 | The facilitator script lists the only think-aloud prompts allowed and forbids hints              | read the script                                                     | Nielsen, _Thinking Aloud: The #1 Usability Tool_, NN/g 2012 |
| TP7 | A pilot session was run and its data excluded                                                    | pilot notes, and the protocol changes they caused                   | ISO 9241-210:2019 (evaluation)                              |
| TP8 | Every participant received the same tasks in a stated order, or the order was counterbalanced    | the session log                                                     | ISO 9241-11:2018 (specified goals)                          |

## Why each one

**TP4 is the row that keeps the results honest.** Criteria written after
watching the sessions drift towards what happened; dated criteria are the only
proof they did not.

**TP3** decides what the test measures. A task that says "click Settings"
tests whether people can follow instructions, not whether they can find
settings.

**TP6** exists because Nielsen names facilitator prompting as the way
think-aloud goes wrong: an untrained prompt changes what the participant does.
