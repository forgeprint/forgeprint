# Assumptions

The job in [`delivery-plan.yaml`](delivery-plan.yaml). An assumption is
**critical** when getting it wrong means redoing a branch. No critical one went
to a worker before the user approved it (§3, F4).

| ID  | Assumption                                                                | Critical | Approved             | Used by    |
| --- | ------------------------------------------------------------------------- | -------- | -------------------- | ---------- |
| A1  | Deleting a project that still has tasks is refused with 409, not cascaded | yes      | user, before fan-out | T2, T4     |
| A2  | Storage stays in memory, as in the blueprint; no database is added        | yes      | user, before fan-out | T0, T2, T3 |
| A3  | Identifiers are UUIDs generated by the server                             | no       | —                    | T0         |
| A4  | A task's project cannot be changed after creation                         | no       | open                 | T3         |

A4 is still open, and the report says so. It was not critical — changing it
later means one route, not a branch — so it did not block fan-out, but nobody
has confirmed it either.
