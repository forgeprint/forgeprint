# Typing decision

Ruby has two gradual type systems and neither is on by default. The decision
is which one, how strict, and how it is kept from sliding back.

| #   | Check                                                                               | How                                                                            | Source                           |
| --- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------- |
| TD1 | One typing approach is recorded: Sorbet, RBS with Steep, or none                    | the ADR; the gems in the Gemfile match it, and there are not both              | Sorbet 0.6; RBS 4.2; Steep 2.1   |
| TD2 | Sorbet: every Ruby file has a sigil                                                 | `grep -rL "# typed:" --include=*.rb app lib packs` prints none                 | Sorbet — strictness levels       |
| TD3 | Sorbet: new files are `typed: strict`; a pull request never lowers a sigil          | `git diff main -U0 -- '*.rb' \| grep "^-# typed:"` compared with the `+` lines | Sorbet — strictness levels       |
| TD4 | Sorbet: `bundle exec srb tc` runs in CI                                             | read the workflow or `config/ci.rb`                                            | Sorbet — adopting Sorbet         |
| TD5 | Sorbet: gem RBIs are generated by Tapioca and committed, never edited by hand       | `sorbet/rbi/gems/` exists; `bin/tapioca gems --verify` passes                  | Tapioca 0.20                     |
| TD6 | Every `T.unsafe` or `T.untyped` in `typed: strict` code has a comment with a reason | `grep -rn "T.unsafe\|T.untyped" app packs` and read each                       | Sorbet — `T.untyped`, `T.unsafe` |
| TD7 | RBS: signatures live in `sig/`, and `bundle exec steep check` runs in CI            | `Steepfile` lists the checked targets; the CI step exists                      | Steep 2.1; RBS 4.2               |

## Why each one

**TD1** because a codebase with Sorbet sigils in some files and RBS
signatures for others has two partial type systems and a type checker that
covers neither fully. Picking one is cheaper than reconciling two.

**TD3** is the ratchet. `typed: strict` requires a signature on every method
and a type on every constant and instance variable; a sigil dropped to
`false` to get a change through removes every one of those checks for the
whole file, and nothing else reports it.

**TD5** because a hand-edited gem RBI is overwritten on the next
`tapioca gems` and, until then, describes a gem version that may not be the
one installed. `--verify` fails when the committed RBIs and the lockfile
disagree.
