# langgraph-agent — architecture and security review

- Date: 2026-09-23
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due
  2026-12-21)
- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Verdict: **MERGE**

## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c)
— and this is the one where that rule earns its place. It is the catalog's
first `agent` blueprint that is not an MCP server, which means it is the first
one that ships a **tool surface with real capability**: the other three expose
an `add` function that does arithmetic, and this one reads files.

The catalog plan ordered this last on purpose, so that the §5c review would be
routine before it was load-bearing. That was the right call, and the blueprint
turns out to be the most security-conscious in the catalog: the tool boundary
is treated as the only defence that works, the refusals are tested before the
happy path, and the escape check runs as a setup step rather than only as a
test.

The manifest claims `tier: community` and `provenance: generated`.

## Findings

### 1. No human-in-the-loop, and the blueprint will be copied for tools that need one — `medium`

- **Where:** `blueprints/langgraph-agent/setup.md:128` (step 8); the absence of
  any `interrupt`
- **Standard:** OWASP Top 10 for Agentic Applications 2026; OWASP LLM 2025,
  **excessive agency** (excessive autonomy)
- **What:** the graph runs assistant → tools → assistant without pause. For a
  read-only tool over a bounded directory that is proportionate.
- **Why it matters:** `AGENTS.md` tells the reader to add tools, and the second
  one will write, send or spend. At that point autonomy without a checkpoint is
  the finding that matters most in the whole agentic top ten, and the graph
  offers no shape for it — LangGraph's `interrupt` is not mentioned in the
  code, only in `overview.md` under what this does not do.
- **Mitigating:** the omission is declared in both documents, and
  `overview.md` says explicitly that "any tool with real consequences should
  have one".
- **Fix:** a commented `interrupt_before=["tools"]` in `build_graph`, or one
  paragraph in `AGENTS.md` under "Adding a tool" showing where the checkpoint
  goes. This is the single most valuable addition this blueprint could take,
  and it is small.

### 2. A refusal is returned to the model as text it can reason about — `low`

- **Where:** `blueprints/langgraph-agent/setup.md:178` (step 8)
- **Standard:** OWASP LLM 2025, sensitive information disclosure
- **What:** `ToolRefused` messages reach the model verbatim — "refusing to read
  outside the notes directory", "no note called X".
- **Why it matters:** this is correct and is the right trade-off, and it is
  still an information channel: "no note called X" distinguishes a missing file
  from a refused path, which is a probe an injected instruction could run
  repeatedly to map the directory.
- **Mitigating:** the directory is bounded and its contents are what the agent
  is for; there is nothing to enumerate that the agent is not already allowed
  to read.
- **Fix:** none at this scope. Worth remembering when a future tool refuses for
  a reason that is itself sensitive — "you are not authorised for tenant 42"
  tells the model, and therefore possibly the user, that tenant 42 exists.

### 3. Nothing bounds cost or rate across invocations — `low`

- **Where:** `blueprints/langgraph-agent/setup.md:118` (step 8)
- **Standard:** OWASP API Security Top 10 2023, **API4:2023 Unrestricted
  Resource Consumption**; Agentic 2026
- **What:** `MAX_TOOL_CALLS` bounds the loop inside one invocation. Nothing
  bounds how many invocations happen or what they cost.
- **Why it matters:** the per-run bound is the harder half and it is present;
  the cross-run bound belongs to whatever calls the agent, which this blueprint
  does not include.
- **Fix:** declared under Cons in `overview.md`. Left open because the control
  lives outside the blueprint's scope.

### 4. `GenericFakeChatModel` proves the graph and not the agent — `info`

- **Where:** `blueprints/langgraph-agent/setup.md:266` (step 10)
- **Standard:** the catalog's rule that a verification must prove what a reader
  thinks it proves
- **What:** the tests queue the messages the fake model will return, then
  assert the graph's behaviour.
- **Why it matters:** it proves routing, the tool node and the bound — which is
  what needs testing and what is normally untested. It proves nothing about
  whether a real model would choose a sensible tool call, and a reader could
  mistake a green suite for "the agent works".
- **Fix:** already stated, in `overview.md` under Cons and in the test file's
  own docstring. Recorded because it is the honest limit of the approach and
  the reason the approach is still right.

## What was checked and found sound

- **The tool is treated as the security boundary, explicitly.** `AGENTS.md`
  states the position — filtering text for prompt injection loses, refusing the
  action does not — and the code follows it: the tool takes a name rather than
  a path, so it cannot express `../` however persuasive the prompt
  (OWASP LLM 2025, excessive agency; Agentic 2026).
- **Two checks, because either alone has a hole.** The shape of the name is
  rejected before resolving, and the resolved path is checked against the root
  after — which is what catches a symlink inside the directory. Most
  implementations do one.
- **Refusals are tested before the happy path**, five cases parameterised. A
  suite that only proves the tool works for the caller you trust proves nothing
  about the caller you do not.
- **The escape check exists outside the test suite** and runs as a setup step,
  so it survives somebody deleting a test file. That is unusual and it is the
  right instinct for the one assertion the blueprint rests on.
- **A refused call becomes a message rather than an exception**, so the agent
  does not die mid-conversation — and a test asserts it (A10, mishandling of
  exceptional conditions).
- **The loop is bounded and the output is bounded.** An agent that can loop can
  loop forever; a tool that can return unlimited text can fill a context
  window. Both have a named constant and a comment.
- **The model is a parameter, not an import**, which is the decision that makes
  everything else testable. A module constructing its own client from the
  environment could only be tested with an API key, which means it would not
  be tested.
- **No provider package is installed, and a step proves it.** The claim "this
  runs without an API key" is checked rather than asserted — and it means the
  suite keeps running on forks, where secrets are not available.
- **Every version pinned with `==`**, CI installs from the same file the recipe
  does, actions pinned by commit SHA (SSDF; SLSA v1.2; A03).
- **No secrets, no personal data, no employer information** (CLAUDE.md §5b).
  `.env*` is git-ignored before any environment file exists.

## Not applicable

- **Authentication, authorization, session management (ASVS 5.0).** No users,
  no server, no requests.
- **OWASP API Security Top 10, except API4.** No API surface.
- **CIS Docker.** No container.
- **Multi-tenancy, migrations, transport security.** No database, nothing
  listening.
- **System prompt leakage (LLM 2025).** There is no system prompt, which is
  itself declared as a gap under Cons.

---

## Verdict

**MERGE.** One `medium`, two `low`, one `info`.

This is the blueprint the §5c review process was built for, and it holds up:
the tool boundary is treated as the security of the program rather than as
input validation, the refusals are tested first, and the one assertion
everything rests on runs outside the test suite.

The `medium` is about the next tool rather than this one. `AGENTS.md` tells the
reader to add tools and the second will write or spend, and nothing in the
graph shows where a human checkpoint goes. A commented `interrupt_before` and a
paragraph would close it, and it is the most valuable small addition available
to this blueprint.

`tier: official` is not available while `provenance: generated` (ADR 0011).
