# streamlit-data-app — architecture and security review

- Date: 2026-09-25
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 and 2026-09-23
  (next re-check due 2026-12-21)
- Reviewer: maintainer's Claude Code agent, `blueprint-arch-review`
- Verdict: **MERGE**

## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
A Streamlit dashboard over a bundled CSV: pandas transforms in `app/data.py`
with no Streamlit import, a thin page in `streamlit_app.py`, and tests at three
levels — unit, `AppTest` driving the widget, and the configuration read
through Streamlit's own loader.

The single most important thing for a reader: **there is no authentication**,
and the design's answer to that is exposure rather than access control — the
server is bound to `127.0.0.1`, a test holds that line, and `overview.md` and
`AGENTS.md` both say what has to exist before it is widened.

The manifest claims `requirements: [testing, ci]`, `tier: community` and
`provenance: generated`. It does not claim `auth`, `file-upload` or `caching`,
so the review does not look for them (see "Not applicable").

## Findings

### 1. No application logging; the server log is the only operational signal — `low`

- **Where:** `blueprints/streamlit-data-app/setup.md:179` (step 10,
  `streamlit_app.py`)
- **Standard:** OWASP Top 10:2025 A09 Security Logging and Alerting Failures;
  OWASP ASVS 5.0, Security Logging and Error Handling chapter
- **What:** the page writes nothing to a log. A `SchemaError` at load reaches
  Streamlit's own logger and the terminal; nothing records who viewed what,
  because there is no "who".
- **Why it matters:** for a loopback dashboard with one viewer this is the
  right amount. The first deployment that widens `server.address` behind a
  proxy will want request and access logging, and the example does not show
  where it goes.
- **Fix:** none at this scope. The logging belongs with the authentication
  that `AGENTS.md` rule 9 makes a precondition of widening the bind address,
  and should be added in the same change.

### 2. The data path is a constant, not configuration — `low`

- **Where:** `blueprints/streamlit-data-app/setup.md:127` (step 9,
  `DATA_FILE`)
- **Standard:** The Twelve-Factor App, III (Config)
- **What:** `DATA_FILE` is computed from the module's location. There is no
  environment variable for it.
- **Why it matters:** correct for a synthetic file committed with the code —
  it is part of the build, not of the deploy. The moment the source becomes a
  real export or a database, the location and any credential are deploy
  configuration.
- **Fix:** already stated where the change will be made: `AGENTS.md` ("When
  you are asked to read a different file or a database") puts the connection
  string in `st.secrets` or the environment and passes it into `app/data.py`.
  Recorded so the next reviewer does not raise it as missing.

### 3. The recipe's strongest running-app proof uses an experimental endpoint — `info`

- **Where:** `blueprints/streamlit-data-app/setup.md:545` (step 22) and
  `setup.md:557` (step 26)
- **Standard:** ADR practice — the decision is recorded where somebody can
  disagree with it
- **What:** `/_stcore/script-health-check` is enabled with
  `--server.scriptHealthCheckEnabled true`, an option Streamlit hides and
  marks experimental. It is enabled on the command line for that run only and
  never enters `.streamlit/config.toml`.
- **Why it matters:** a Streamlit upgrade may remove it, and step 26 would
  then fail for a reason unrelated to the project. The documented
  `/_stcore/health` check in step 24 stands on its own.
- **Fix:** none. `overview.md` (Cons) and `CHANGELOG.md` both record it; if it
  disappears, drop step 26 and rely on `AppTest`.

### 4. No dependency lockfile — `info`

- **Where:** `blueprints/streamlit-data-app/setup.md:21` (step 3)
- **Standard:** OWASP Top 10:2025 A03 Software Supply Chain Failures; SLSA
  v1.2
- **What:** direct dependencies pinned with `==`; transitive ones — pyarrow,
  numpy, altair, the web server stack — resolve at install time within
  Streamlit's declared ranges.
- **Why it matters:** the trade-off every Python blueprint here carries,
  heavier here because Streamlit's dependency tree is large. Recorded so the
  next reviewer does not re-derive it.

## What was checked and found sound

- **Exposure matches the absence of authentication.** `server.address =
"127.0.0.1"` in the committed config, a test that fails if it changes, and
  step 23 reads the bound address back from the server's own log as
  `127.0.0.1`. `overview.md` names authentication first under "What it is NOT
  for", and `AGENTS.md` rule 9 names the two ways to add it before widening
  the bind (ASVS 5.0, Authorization chapter — applied as "what is exposed
  without it", since the blueprint claims no authorization).
- **XSRF protection is on, and proved on the running server.** Written
  explicitly in the config, asserted by `tests/test_config.py`, and step 25
  requires the `_streamlit_xsrf` cookie on a live response — a check of the
  behaviour, not only of the file. CORS protection is written down as on too
  (ASVS 5.0, Web Frontend Security — browser origin separation).
- **Usage statistics off, and the test proves it came from this project.**
  Streamlit's default for `browser.gatherUsageStats` is true. The test checks
  both the value and, with `get_where_defined`, that the project's file set
  it, so a developer's global config cannot make it pass on one machine only
  (ASVS 5.0, Data Protection chapter).
- **Exception details stay out of the page.** `showErrorDetails = "type"`
  instead of the default `"full"`; tracebacks go to the terminal. The config
  test holds it (OWASP Top 10:2025 A10 Mishandling of Exceptional Conditions;
  ASVS 5.0, Security Logging and Error Handling).
- **Bad data fails at the boundary, by name.** `load_sales` refuses a missing
  column, a value of the wrong type, a date not in `%Y-%m-%d` and negative
  units, each with a test. `AGENTS.md` rule 5 forbids catching `SchemaError`
  to render an empty table, which is the failure mode that turns broken data
  into a plausible dashboard (A10; ASVS 5.0, Validation and Business Logic).
- **Output encoding.** Every data value reaches the browser through
  `st.dataframe`, `st.metric` or a chart, which escape what they render.
  Nothing uses `unsafe_allow_html`, and `AGENTS.md` rule 11 says why not to
  start (ASVS 5.0, Encoding and Sanitization).
- **Boundary and dependency direction.** `app/data.py` imports pandas and
  nothing from Streamlit; the page imports `app.data`, never the reverse.
  `AGENTS.md` rules 1 and 2 state the dependency rule and the reason, and the
  unit tests exercise the inner module with no Streamlit runtime (Clean
  Architecture, dependency rule; hexagonal ports and adapters).
- **The tests prove the claims.** `testing`: unit tests for every transform
  including the empty selection, and `AppTest` tests that set the multiselect
  and assert the table, the metric and the chart spec — not "it imported".
  `ci`: the generated workflow runs ruff lint, ruff format check and the
  tests from the same requirements file the recipe installs.
- **Cache semantics.** One `st.cache_data` on a zero-argument loader, so one
  entry; `st.cache_data` returns a copy per run. `AGENTS.md` rule 7 warns
  against `st.cache_resource` for a DataFrame, which would share one mutable
  object across sessions.
- **Secrets have a safe place to go.** `.streamlit/secrets.toml`, where
  `st.secrets` reads from, is in the generated `.gitignore`, and `AGENTS.md`
  rule 10 says secrets go there or in the environment (Twelve-Factor III;
  CLAUDE.md §5b).
- **The CI workflow.** Actions pinned by commit SHA with the version in a
  comment — `actions/checkout` v7.0.1 and `actions/setup-python` v7.0.0, both
  checked against the tags on 2026-09-25 — and `permissions: contents: read`
  (SLSA v1.2; NIST SSDF PS.1; A03).
- **The recipe.** Every version pinned with `==` and verified against PyPI on
  2026-09-25, with wheels for Python 3.13. The server runs on a port the
  operating system chooses, read back from the log rather than assumed; it is
  started in the background and stopped by process id. Network access is
  PyPI and loopback only.
- **No secrets, no personal data, no employer information** in any file
  (CLAUDE.md §5b). The CSV is twenty synthetic rows.

## Not applicable

- **Authentication, session management, authorization (ASVS 5.0).** Not
  claimed. `overview.md` says so plainly and the design compensates with a
  loopback bind that a test holds. This is the item a reader must not miss,
  and it is stated in both places they read.
- **File handling (ASVS 5.0, File Handling chapter).** No upload. `AGENTS.md`
  says what adding one requires — `server.maxUploadSize`, the same column
  contract, and an `AppTest` test of a bad upload — and `CHANGELOG.md` lists
  it under Planned.
- **OWASP API Security Top 10.** `project_type: data`; there is no API beyond
  Streamlit's own endpoints, which are not part of the blueprint's surface.
- **OWASP LLM 2025, Agentic 2026, MCP guidance.** No model, no tools.
- **CIS Docker.** No container.
- **WCAG.** `accessibility` is not claimed. Streamlit's components are what a
  reader gets, and nothing here is hand-built.
- **Rate limiting, multi-tenancy, migrations, transport security.** None
  claimed, none implied; the server is loopback and plain HTTP by design, and
  TLS belongs to whatever eventually sits in front of it.

---

## Verdict

**MERGE.** No `critical`, `high` or `medium` findings. Two `low`s — logging
and the data path as configuration — are both about the change that turns
this from a loopback tool into something reachable, and `AGENTS.md` already
names that change and what must come with it. Two `info`s record trade-offs
(an experimental endpoint in the recipe's proof, no lockfile) so they are not
re-derived.

`tier: official` is not available while `provenance: generated` (ADR 0011).
