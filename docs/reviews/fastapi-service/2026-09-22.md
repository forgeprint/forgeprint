# fastapi-service — architecture and security review

- Date: 2026-09-22
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due 2026-12-21)
- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Verdict: **CHANGES** — findings closed the same day; see _Resolution_

## Summary

A FastAPI service with SQLAlchemy async, bearer token verification, a container
image and CI. The three decisions that usually go wrong here went right:
verification lives in one module and nothing else reads the `Authorization`
header, a missing token answers 401 rather than the framework's 403, and there
is one engine per process.

It also avoids the fault both .NET API blueprints had — authorization is not
claimed to be default-deny, so nothing promises a control that is not there.

The findings are smaller, and one of them is a check that passes for the wrong
reason.

The manifest claims `tier: official`. No `critical` or `high` findings are
open, so **rule 23 does not block that tier**.

## Findings

### 1. The container check runs with a database URL whose driver is not installed — `medium`

- **Where:** `blueprints/fastapi-service/setup.md:436` (step 20) against
  `setup.md:22` (step 2, the `postgres` branch)
- **Standard:** OWASP Top 10:2025 **A02 Security Misconfiguration**; the
  catalog's own rule that a verification has to prove something
- **What:** the container is started with
  `DATABASE_URL="sqlite+aiosqlite:///./app.db"` regardless of the chosen
  option. Under `database=postgres`, `requirements.txt` installs `asyncpg` and
  not `aiosqlite`, so that URL cannot be opened by the image it is given to.
- **Why it matters:** the check passes, because the engine is created lazily
  and `/health` touches nothing. So it proves the process starts and answers,
  which is worth proving — but a reader will reasonably read it as "the
  container works with this configuration", and the first request that touches
  the database would fail with a missing driver. A verification that passes for
  a reason other than the one the reader assumes is the kind that stops being
  checked.
- **Fix:** pass the URL that matches the option — a Postgres URL under
  `postgres`, the sqlite one under `sqlite` — and say in the step that the
  liveness endpoint answers without the database being reachable, which is why
  no database needs to be running for this check.

### 2. `Settings` has no default for `DATABASE_URL` or `JWT_SECRET`, and nothing says what happens — `low`

- **Where:** `blueprints/fastapi-service/setup.md:66` (step 5)
- **Standard:** Twelve-Factor III (config); OWASP Top 10:2025 **A10
  Mishandling of Exceptional Conditions**
- **What:** both are required fields, so `Settings()` raises a
  `ValidationError` when either is missing. That is the right behaviour — it
  fails closed at the first use — but `get_settings` is called from a
  dependency, so the failure surfaces as a 500 on the first request rather than
  at startup.
- **Why it matters:** the same distinction that cost `dotnet-web-api` a
  revision: failing closed at startup is a service that does not come up;
  failing closed on a request is a service that looks healthy and answers 500
  to everything. `/health` would still return 200, so an orchestrator would
  consider the container ready.
- **Fix:** call `get_settings()` once during application startup — a lifespan
  handler, or simply at import time in `main.py` — so a missing variable stops
  the process rather than every request.

### 3. Rate limiting is absent and not declared absent — `low`

- **Where:** `blueprints/fastapi-service/overview.md`, "What it is NOT for"
- **Standard:** OWASP API Security Top 10 2023, **API4:2023 Unrestricted
  Resource Consumption**
- **What:** no rate limiting, which is a legitimate scope decision, but the
  list a reader consults to find out what is missing does not mention it.
- **Why it matters:** an undocumented omission reads as an oversight.
- **Fix:** one line, the same as `dotnet-web-api` 1.0.5.

### 4. The base image moves within a minor — `info`

- **Where:** `blueprints/fastapi-service/setup.md:399` (step 14)
- **Standard:** CIS Docker Benchmark, image scope
- **What:** `python:3.13-slim` is not a digest.
- **Why it matters:** identical trade-off to the .NET blueprints, and the same
  answer: a digest is byte-exact and also stops security patches arriving.
  Recorded so the next reviewer does not raise it again.
- **Fix:** none required; a sentence in `overview.md` would match what
  `dotnet-web-api` now says.

## What was checked and found sound

- **One place verifies tokens.** `app/security.py` is the only module that
  reads `Authorization` or calls `jwt.decode`, and every protected route
  depends on `current_claims`. There is no second definition of
  "authenticated" (OWASP ASVS 5.0, Authentication chapter).
- **`jwt.decode` is called with `algorithms=` and an audience.** Both are the
  controls that matter: without the algorithm list the library accepts tokens
  signed the wrong way, and without an audience a token for another service
  works here. **A test forges a token with a different secret and asserts 401**
  — the test that fails the day verification is reduced to decoding
  (OWASP API2:2023).
- **A missing token is 401, not 403.** `HTTPBearer(auto_error=False)` exists so
  this module can answer "who are you" rather than the framework answering "you
  may not".
- **One engine per process.** `app/db.py` holds it, lazily, and the comment
  says why a second one halves what the database can serve.
- **Configuration is environment-only and strict.** `extra="forbid"` means a
  misspelled variable is an error rather than a silently ignored line.
- **`/health` touches nothing**, with the reason in the docstring (OWASP A09;
  Twelve-Factor IX).
- **Non-root container**, multi-stage, no tests or `.env` in the image
  (`.dockerignore`), CIS Docker image scope.
- **Every version pinned with `==`**, including the development set, and CI
  installs from the same file it ships (SSDF; SLSA).
- **Tests run in-process through the ASGI transport** — no server, no port, no
  database, four tests in under a second, which is what makes it plausible that
  anybody runs them.
- **Authorization is not overclaimed.** Unlike the .NET API blueprints before
  today, nothing here says endpoints are protected by default; each protected
  route declares its dependency, and `overview.md` does not promise otherwise.

## Not applicable

- **Multi-tenancy controls (OWASP API1 BOLA).** Not claimed;
  `overview.md` says plainly that tenancy is absent and that retrofitting it is
  the expensive path.
- **Token issuance, password storage, session management (ASVS).** The service
  verifies tokens and issues none, and `overview.md` says a service that does
  both is usually two services.
- **OWASP LLM 2025 and Agentic 2026.** `project_type: api`.
- **CIS Docker host and daemon controls.** A blueprint does not configure the
  reader's daemon.
- **Migrations.** None shipped, and the omission is documented as a decision
  the reader should make when the first model is real.

## Resolution

Closed in **1.0.1**, on the day of the review.

| #   | Severity | Closed by                                                                                                                                                                                                                                                                                                       |
| --- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `medium` | The container check passes the URL matching the driver the chosen option installed, and the step says the liveness endpoint answers without a database — which is why the check means something without one running                                                                                             |
| 2   | `low`    | `get_settings()` is called from a lifespan handler, so a missing variable stops the process rather than answering 500 to every request while `/health` still returns 200. Not at import time: the first attempt was, and it broke the test suite, which imports the app and supplies its environment afterwards |
| 3   | `low`    | Rate limiting added to "What it is NOT for", citing API4:2023                                                                                                                                                                                                                                                   |
| 4   | `info`   | `overview.md` states the base-image trade-off rather than changing it                                                                                                                                                                                                                                           |

**`tier: official` was never blocked** — this blueprint had no `high` findings.

Finding 2 took two attempts, which is the same lesson `dotnet-web-api` learned on
the same day in a different language: _"fail closed" has to mean closed at
startup, and the place that starts the process is not always the place that
imports the module."_ The lifespan handler runs under `uvicorn` — so the
container step proves it — and not under the in-process transport the tests
use, which is the split that was wanted.
