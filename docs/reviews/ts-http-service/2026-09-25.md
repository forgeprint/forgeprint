# ts-http-service — architecture and security review

- Date: 2026-09-25
- Blueprint version: 1.2.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due
  2026-12-21)
- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Scope: the `framework: express` branch added in 1.2.0, and the steps it shares
  with the `hono` branch. The Hono branch is unchanged apart from a neutral
  install check and README line; its review is
  [2026-09-23](2026-09-23.md) and stays current.
- Verdict: **MERGE**

## Summary

`options.framework` adds Express 5 beside Hono, per D12 of the expansion plan,
rather than a second slug for the same language, type and requirements
(ADR 0001).

The Express branch keeps the design and every check the Hono branch has:
authentication decided in one module, protection by placement on a router, a
route-table test, a forged-token test, configuration that fails closed, and
the unauthenticated request proved refused against the running image by the
same shared step. Express needed two controls Hono did not — a terminal error
handler and `x-powered-by` off — and both are present and tested.

The single thing a reader should know: in Express, placement is also order,
and the route-table test only understands routers mounted at `/`.

## Findings

### 1. The route-table test reads route paths, not mount paths — `low`

- **Where:** `blueprints/ts-http-service/setup.md:476` (step 6, express),
  `routesOf`
- **Standard:** OWASP API Security Top 10 2023, **API5:2023 Broken Function
  Level Authorization**
- **What:** the walker descends into mounted routers and collects each route's
  own path. A router mounted at `/v1` yields `/items`, and the test then
  requests `/items` rather than `/v1/items`. Because the protected router's
  middleware answers 401 to every request that reaches it, the wrong URL is
  refused and the test passes whether or not `/v1/items` is public.
- **Why it matters:** Express 5's router no longer keeps a mount path on its
  layers in a form that can be read back, so the test cannot recover it. The
  blueprint mounts nothing below `/`, so today the check is exact.
- **Mitigating:** `AGENTS.md` says to mount routers at `/` or extend the test
  first; `overview.md` names it under Cons.
- **Fix:** none at this scope. Whoever mounts the first router under a prefix
  records the prefix beside it and has the walker prepend it.

### 2. The walk depends on `router.stack`, which Express does not document — `low`

- **Where:** `blueprints/ts-http-service/setup.md:476` (step 6, express)
- **Standard:** OWASP API5:2023 (the control the test exists to keep)
- **What:** `app.router` is documented in the Express 5 API; the shape of its
  `stack` — `layer.route`, `layer.handle.stack` — is not.
- **Why it matters:** a minor Express release could change it, and a walk that
  stops descending would find only `GET /health` and check nothing.
- **Mitigating, and why this is `low`:** the test asserts that at least one
  protected route was found and checked, so a walk that stops descending fails
  loudly rather than passing. That assertion was added in this review; before
  it, the test only refused an empty table, which `/health` alone satisfied.
- **Fix:** done.

### 3. Placement in Express is also order — `info`

- **Where:** `blueprints/ts-http-service/setup.md:421` (step 5, express)
- **Standard:** OWASP API5:2023; OWASP Top 10:2025 **A01 Broken Access Control**
- **What:** a route declared on `app` above `app.use(protectedRoutes)` is
  public; one declared below it is refused, but only because the router's
  middleware sees every request.
- **Why it matters:** it is the same class as finding 1 of the 2026-09-23
  review, which the route-table test closed. Recorded so that the second way
  to be right by accident is written down.
- **Fix:** stated in `AGENTS.md` ("In Express, order is placement"); nothing
  else required.

## What was checked and found sound

- **Authentication is identical in substance.** `jwtVerify` with
  `algorithms: ['HS256']`, `audience`, `issuer` and
  `requiredClaims: ['exp', 'sub']`; 401 with no reason for a missing or
  rejected token (OWASP API2:2023; ASVS 5.0 token verification).
- **Async middleware is safe without a wrapper.** Express 5 forwards a
  rejected promise to the error handler; the comment says so, because advice
  written for Express 4 says the opposite.
- **Errors do not leak.** Express's default error handler renders the stack
  trace whenever `NODE_ENV` is not `production`, and `node:22-alpine` does not
  set it. `hideErrors` is the last handler, answers a JSON 500 and logs the
  detail; a test throws a marked error through it and asserts the marker is
  absent from the response (OWASP Top 10:2025 **A10 Mishandling of Exceptional
  Conditions**).
- **No framework banner.** `x-powered-by` is disabled and a test asserts the
  header is absent (OWASP Top 10:2025 **A02 Security Misconfiguration**).
- **The claims are typed.** `Locals = { claims: JWTPayload }` on
  `Response<unknown, Locals>` makes `res.locals.claims` checked rather than
  `any` — the Express equivalent of Hono's `Env`.
- **The forged token is tested**, and so is the valid one, through a real
  listener on a loopback port the operating system picks, so parallel runs
  cannot collide and nothing is exposed beyond `127.0.0.1`.
- **A failed listen is not swallowed.** Express 5 hands a listen error to the
  callback rather than throwing; `main.ts` rethrows it so the process exits
  instead of running with nothing bound (A10).
- **Configuration fails closed at module scope**, unchanged (Twelve-Factor III;
  A10).
- **The shared steps prove the running image for both branches.** Steps 15–21
  are not guarded: the same image build, the same non-root user, the same
  `/health` and the same 401 from `/items` (CIS Docker, image scope).
- **Pins verified on 2026-09-25:** `express` 5.2.1 is npm `latest` (the 4.x
  line is `latest-4`, 4.22.3); `@types/express` 5.0.6 is current.
- **No secrets, no personal data, no employer information** (CLAUDE.md §5b).
  The test secrets are labelled as not real.

## Not applicable

- **Input validation.** Neither branch accepts a request body, a query or a
  path parameter; `/items` takes nothing. There is nothing to validate, and
  `overview.md` does not claim it.
- **Graceful shutdown.** Absent in both branches and stated under "What it is
  NOT for".
- **Findings 2–4 of 2026-09-23** (alpine rather than distroless, HMAC, no
  committed lockfile) apply to the Express branch unchanged, because the
  Dockerfile, the token scheme and the install step are shared. They are not
  re-raised.
- **OWASP LLM 2025 and Agentic 2026.** `project_type: api`.

---

## Verdict

**MERGE.** Two `low`, one `info`, no `critical` or `high`.

Finding 2 was fixed before this report was written: the route-table test now
fails when it checks no protected route, which is the failure mode an
undocumented internal makes likely.

`tier: official` is not available while `provenance: generated` (ADR 0011).
