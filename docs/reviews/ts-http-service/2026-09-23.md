# ts-http-service — architecture and security review

- Date: 2026-09-23
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due
  2026-12-21)
- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Verdict: **MERGE**

## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
The catalog's fifth `api` and second written in a day, after `go-http-service`.

It carries the same design and therefore the same central weakness: Hono, like
Gin, has no framework-level default-deny, so "protected" is a property of which
application a route is mounted on. It also carries the same strengths — the
configuration fails closed at startup, and the unauthenticated request is
proved refused rather than assumed.

Two things are specifically better here than in the Go blueprint, and one is
specifically worse. Better: the tests exercise the real router with no server
at all, because a Hono app is a fetch handler; and the context is typed, so
`c.get('claims')` is checked rather than `any`. Worse: the image is
`node:22-alpine` rather than distroless, and it ships a shell.

The manifest claims `tier: community` and `provenance: generated`.

## Findings

### 1. A route mounted on `app` rather than `protectedRoutes` is public — `medium`

- **Where:** `blueprints/ts-http-service/setup.md:156` (step 5)
- **Standard:** OWASP API Security Top 10 2023, **API5:2023 Broken Function
  Level Authorization**; OWASP Top 10:2025 **A01 Broken Access Control**
- **What:** the middleware is mounted on a sub-application. A handler
  registered on `app` instead of on `protectedRoutes` is reachable without a
  token.
- **Why it matters:** the same class as the `medium` in `go-http-service` and
  the `high` both .NET blueprints were fixed for. The line immediately above —
  `app.get('/health', ...)` — is the shape somebody copies.
- **Mitigating, and why this is `medium`:** the rule is stated twice in
  `AGENTS.md`, the exception carries its reason, and the container check
  asserts the 401 for the route that exists.
- **Fix:** Hono exposes `app.routes`, so a test that fails on any path outside
  an allow-list which is not behind the middleware is a dozen lines. It belongs
  in whatever change adds the second protected route.

### 2. The runtime image ships a shell and a package manager — `low`

- **Where:** `blueprints/ts-http-service/setup.md:296` (step 9)
- **Standard:** CIS Docker Benchmark, image scope
- **What:** the final stage is `node:22-alpine`. It runs as the non-root `node`
  user and `npm prune --omit=dev` removes the development tree, but the image
  still contains a shell, `npm`, and the rest of a distribution.
- **Why it matters:** `go-http-service`, reviewed the same day, uses a
  distroless base with nothing in it but the binary. The difference is the
  runtime rather than the blueprint — Node needs an interpreter — but a
  `distroless/nodejs` base exists and would remove the shell.
- **Fix:** `gcr.io/distroless/nodejs22-debian12` is a drop-in for the final
  stage and worth trying. Not done here because it changes how the entry point
  is invoked, and an unverified change to the one step that proves the image
  runs would be worse than the finding. `overview.md` states the gap under
  Cons.

### 3. HMAC means the verifier holds the signing key — `low`

- **Where:** `blueprints/ts-http-service/setup.md:98` (step 4)
- **Standard:** OWASP ASVS 5.0, Cryptography; OWASP API2:2023
- **What:** HS256 with a shared secret. `algorithms: ['HS256']` correctly
  prevents algorithm confusion; the secret that verifies is the secret that
  signs.
- **Why it matters:** identical to the finding in `go-http-service`. Fine for
  one internal issuer, wrong the moment a third party issues tokens.
- **Fix:** stated in `overview.md`. Recorded so it is not raised again.

### 4. No committed lockfile — `low`

- **Where:** `blueprints/ts-http-service/setup.md:24` (step 1)
- **Standard:** OWASP Top 10:2025 **A03 Software Supply Chain Failures**;
  SLSA v1.2
- **What:** direct dependencies are pinned exactly; `npm install` resolves the
  rest at build time, and the Dockerfile copies `package-lock.json` only if one
  happens to exist.
- **Why it matters:** the same trade-off the whole catalog carries, but it is
  more visible here than in `go-http-service`, where `go.sum` gives hash-level
  verification on every subsequent build. Worth stating as the gap rather than
  as a tie.
- **Fix:** none required at this scope; `overview.md` says it plainly.

## What was checked and found sound

- **The unauthenticated request is proved refused, twice** — through the fetch
  handler and again against the running container.
- **A forged token is tested**: signed with a different secret, expected 401 —
  the test that fails the day verification is reduced to decoding
  (OWASP API2:2023).
- **Every `jwtVerify` option is present and explained**: `algorithms`
  (algorithm confusion), `audience` (a token for another service), `issuer`,
  `requiredClaims: ['exp', 'sub']` (a token valid forever).
- **401, not 403**, with the distinction written down, and the rejection reason
  is not returned to the caller.
- **Configuration fails closed at startup**, at module scope in `main.ts` —
  the fault three earlier blueprints in this catalog had to be fixed for
  (OWASP Top 10:2025 A10).
- **`/health` touches nothing** and says why (OWASP A09; Twelve-Factor IX).
- **The context is typed.** `Env = { Variables: { claims: JWTPayload } }` is
  what makes `c.get('claims')` checked rather than `any`. Small, and it decides
  whether the type checker is any use inside a handler.
- **The tests need no server**, so they cover routing and middleware in
  milliseconds — which is what makes it plausible that anybody runs them.
- **The image runs as `node`, not root**, and development dependencies are
  pruned before the final stage (CIS Docker image scope).
- **Actions pinned by commit SHA** with the version in a comment (A03).
- **No secrets, no personal data, no employer information** (CLAUDE.md §5b);
  the credential-shaped values are labelled as not real.

## Not applicable

- **BOLA / object-level authorization (API1:2023).** No objects, no owner.
- **Multi-tenancy, migrations, pooling, transaction boundaries.** No database.
- **Token issuance, password storage, session management (ASVS 5.0).**
  Verifies only.
- **OWASP LLM 2025 and Agentic 2026.** `project_type: api`.
- **CIS Docker host and daemon controls.** A blueprint does not configure the
  reader's daemon.

---

## Verdict

**MERGE.** One `medium`, three `low`.

The `medium` is the same finding as in `go-http-service` and has the same fix,
which is worth noting as a pattern rather than a coincidence: frameworks
without a default-deny make route placement a security decision, and a catalog
that ships several of them should eventually carry that route-table test as a
shared idea rather than rediscovering it per blueprint.

`tier: official` is not available while `provenance: generated` (ADR 0011).
