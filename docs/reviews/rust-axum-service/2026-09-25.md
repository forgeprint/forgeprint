# rust-axum-service — architecture and security review

- Date: 2026-09-25
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due
  2026-12-21)
- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Verdict: **MERGE**

## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
The catalog's first Rust API, and the first `api` blueprint whose recipe runs
its tests against a real Postgres and proves object-level authorization.

The review found one `high` in the first draft: `axum::serve` gives hyper no
timer, so no header-read timeout applies and a slow client holds a connection
indefinitely. It was fixed before the pull request opened, with a test that
was watched failing without the fix. What remains open is disclosed in
`overview.md`: no TLS to the database, no rate limiting, one shared HMAC key.

The manifest claims `tier: community` and `provenance: generated`.

## Findings

### 1. No header-read timeout under `axum::serve` — `high`, resolved in 1.0.0

- **Where:** first draft of `src/main.rs`; now
  `blueprints/rust-axum-service/setup.md:573` (step 9, `src/server.rs`) and
  `:627`
- **Standard:** OWASP API Security Top 10 2023, **API4:2023 Unrestricted
  Resource Consumption**
- **What:** axum 0.8.9's `serve` builds hyper's connection with
  `Builder::new(TokioExecutor::new())` and no timer. hyper 1.11.1 documents
  that `header_read_timeout` takes effect only with a timer, so its 30 second
  default never applies. tower-http's `TimeoutLayer` starts once the request
  exists, which is after the headers. The same client also held up graceful
  shutdown, which waits for every connection with no deadline.
- **Why it matters:** a client that sends a header line every few seconds
  keeps a connection and a task for as long as it likes, and a handful of them
  keep a replica from exiting until the orchestrator kills it mid-request. A
  reader would see `TimeoutLayer` and believe timeouts were handled. Found by
  reading the axum and hyper sources, not the documentation.
- **Fix (done):** `src/server.rs` serves through hyper's HTTP/1 builder with
  `TokioTimer` and a 5 second `header_read_timeout`, and bounds the drain at 8
  seconds, under `docker stop`'s 10. `a_client_that_never_finishes_its_headers_is_disconnected`
  and `shutdown_does_not_wait_forever_for_a_slow_client` each failed when its
  limit was removed by hand, and pass with it.

### 2. The database connection is not encrypted — `medium`

- **Where:** `blueprints/rust-axum-service/setup.md:50` (step 2, `Cargo.toml`)
- **Standard:** OWASP ASVS 5.0, **V12 Secure Communication** (TLS for
  connections to backend components)
- **What:** sqlx is built without a TLS backend, to keep compile time down, so
  the connection string cannot ask for `sslmode=require`.
- **Why it matters:** on a shared network the credentials and every row cross
  it in clear text. On a container network next to the database it is the
  common arrangement; against a managed Postgres it will not even connect,
  because those usually require TLS.
- **Mitigating:** disclosed in `overview.md` under "What it is NOT for", with
  the feature name to add and the URL parameter to set.
- **Fix:** left open as a documented scope decision. The obvious next version
  adds `tls-rustls-ring-webpki` behind a sentence in `AGENTS.md`.

### 3. Nothing bounds how often a caller can hit a route — `low`

- **Where:** `blueprints/rust-axum-service/overview.md`, "What it is NOT for"
- **Standard:** OWASP API Security Top 10 2023, **API4:2023**
- **What:** no rate limiting. The body limit, the request timeout and the
  header timeout bound one request; nothing bounds many.
- **Fix:** declared as absent, with the gateway named as the usual owner.
  Left open because the declaration is the mitigation, not the control.

### 4. One shared HMAC key, and no rotation — `low`

- **Where:** `blueprints/rust-axum-service/setup.md:381` (step 7,
  `src/auth.rs`)
- **Standard:** OWASP ASVS 5.0, **V9 Self-contained Tokens** and **V11
  Cryptography**
- **What:** HS256 with the secret from `JWT_SECRET`. The algorithm is fixed in
  code, the key must be at least 32 bytes (RFC 7518 §3.2), and `exp`, `iss`,
  `aud` and `sub` are required.
- **Why it matters:** anything that can verify a token can mint one, and
  rotating the key means a moment where old tokens fail.
- **Fix:** stated in `overview.md`. Recorded so the next reviewer does not
  raise it as an oversight.

### 5. A crate with a standing advisory is compiled, and CI does not scan — `low`

- **Where:** `blueprints/rust-axum-service/setup.md:45` (step 2,
  `jsonwebtoken` with `rust_crypto`) and `:1383` (step 16, CI)
- **Standard:** OWASP Top 10:2025 **A03 Software Supply Chain Failures**; NIST
  SSDF **RV.1** (identify vulnerabilities continuously)
- **What:** the `rust_crypto` backend pulls in `rsa` 0.9.10, which carries
  RUSTSEC-2023-0071 (a timing side channel, no fixed release). The service
  accepts only HS256, so the RSA code is never reached. The generated CI runs
  no advisory check.
- **Why it matters:** unreachable today; reachable the day somebody adds RS256
  for a JWKS issuer, and nothing in CI would say so.
- **Fix:** add an advisory scan (`cargo audit` or `cargo deny`) when the
  verifier grows an asymmetric algorithm. Named in `overview.md` under
  trade-offs.

### 6. Ids are sequential — `info`

- **Where:** `blueprints/rust-axum-service/setup.md:87` (step 4, migration)
- **Standard:** OWASP API Security Top 10 2023, **API1:2023 Broken Object
  Level Authorization**
- **What:** `BIGINT GENERATED ALWAYS AS IDENTITY`. Guessable, but every read
  is filtered on the owner (`:542`, `:557`), and another caller's id answers
  404 — tested.
- **Fix:** none needed for authorization. The count leak is stated in
  `overview.md`.

### 7. Base images: the runtime by digest, the builder by tag — `info`

- **Where:** `blueprints/rust-axum-service/setup.md:1345` and `:1360` (step 14)
- **Standard:** CIS Docker Benchmark v1.8.0, image and Dockerfile scope
  (pinned base images)
- **What:** `gcr.io/distroless/cc-debian13:nonroot` is pinned by digest;
  `rust:1.98.1-slim-trixie` is an exact version tag, which Docker Hub re-pushes
  for Debian updates.
- **Why it matters:** only the builder can move, and what it produces is
  locked by `Cargo.lock` and `--locked`. What ships cannot move.

## What was checked and found sound

- **Deny by default.** `require_bearer` wraps the whole router and admits only
  `PUBLIC_PATHS`; `a_path_no_route_matches_still_needs_a_token` proves routes
  nobody has written are covered (OWASP API5:2023, A01:2025). The path is
  compared exactly, so `/health/` or `/%68ealth` are not public — and only
  `/health` and `/ready` are routed to the public handlers anyway.
- **Fail closed twice.** The `Caller` extractor returns 401 when the
  middleware did not run, so a handler cannot receive an anonymous caller.
- **Object-level authorization is proved.** `owner = $n` in every query, 404
  for another caller's note, and `a_caller_cannot_read_another_callers_note`
  exercises the read, the list and the create (API1:2023). The owner cannot be
  supplied by the client: `deny_unknown_fields`, tested
  (API3:2023, mass assignment).
- **Token validation is tested case by case**: another secret, expired, no
  `exp`, wrong audience, wrong issuer, no subject, and an unsigned `alg: none`
  token (ASVS V9). A valid token is accepted in the same suite, so the refusals
  are not a verifier that refuses everything.
- **401 with `WWW-Authenticate: Bearer`** (RFC 6750 §3), and the reason for a
  refusal is not returned.
- **Errors are RFC 9457 problem documents** everywhere, including 404, 405,
  413 and 408 written by axum and tower-http; `Problem::internal` logs the
  cause and returns nothing of it (ASVS V16, OWASP A10:2025).
- **Configuration fails closed at startup**, with the variable named; the
  database wait is bounded; `Config`'s `Debug` is hand-written so neither the
  secret nor the database password reaches a log (Twelve-Factor III, ASVS
  V13). Tested.
- **Liveness and readiness are separate**, and readiness has its own deadline
  (A09:2025; Twelve-Factor IX). Tested with an unreachable database.
- **Body limit 16 KiB, request timeout 10 s, header timeout 5 s, drain 8 s**,
  each with a test (API4:2023).
- **Graceful shutdown on SIGTERM**, proved by the recipe against the image:
  `docker stop` gives exit code 0 and a `stopped` log line.
- **Logs** are JSON, one line per request with method, path, status and
  latency; headers are not recorded, so the token never reaches a log
  (A09:2025).
- **Migrations** are embedded, append-only by checksum, rebuilt on change by
  `build.rs`, and applied under Postgres's advisory lock.
- **The container** is distroless, non-root (`nonroot:nonroot`, asserted by the
  recipe), and carries only the binary; tests, `.git` and the CI files are in
  `.dockerignore` (CIS Docker, image scope).
- **Supply chain**: exact `=` pins, a committed `Cargo.lock`, `--locked`
  everywhere, `unsafe_code = "forbid"`, actions pinned by commit SHA,
  `permissions: contents: read`, `persist-credentials: false`, and an MSRV job
  that holds `rust-version` (A03:2025, SLSA build track).
- **No secrets, no personal data, no employer information** (CLAUDE.md §5b).
  Every credential-shaped value reads `local-development-only-not-a-real-secret`
  or `not-a-real-secret-only-for-tests`.

## Not applicable

- **Token issuance, password storage, sessions (ASVS V6, V7).** Verifies only;
  `overview.md` says so.
- **Roles and function-level permissions beyond authentication.** Not claimed:
  a caller owns rows and nothing finer.
- **Multi-tenancy.** Not claimed; `overview.md` points at
  `dotnet-multitenant-saas-api`.
- **CORS and browser concerns.** No browser is expected to call it.
- **OWASP LLM 2025 and Agentic 2026.** `project_type: api`.
- **CIS Docker host and daemon controls.** A blueprint does not configure the
  reader's daemon.

---

## Verdict

**MERGE.** One `high` resolved before the pull request, one `medium`, three
`low`, two `info`, none open above `medium`.

The `medium` is a scope decision a reader is told about: the connection to
Postgres is unencrypted, which is normal on a container network and wrong
across a shared one. It does not block `community`, and it would be the first
thing to settle before this blueprint is proposed for `verified`.
