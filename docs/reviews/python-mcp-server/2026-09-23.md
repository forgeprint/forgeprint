# python-mcp-server — architecture and security review

- Date: 2026-09-23
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due
  2026-12-21)
- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Verdict: **MERGE**

## Summary

A generated blueprint, which is why this review is not optional (ADR 0011,
CLAUDE.md §5c). It is the third MCP server blueprint in the catalog and is
deliberately parallel to the two hand-written ones: the same two transports,
the same shape of test, the same claim about `Origin`.

The parallel is the reason it reviews well. The two `high` findings the other
MCP blueprints carried — an HTTP transport on a loopback port with no origin
check, and configuration read too late to fail at startup — were closed in
those blueprints yesterday, and this one was written after that. It does not
repeat either.

Where it differs is worth noting: the other two write the origin guard by hand
as middleware; this one uses the SDK's own `TransportSecuritySettings`, which is
on by default. Less code, and the default is the safe one.

The manifest claims `tier: community` and `provenance: generated`. No `critical`
or `high` findings are open, and `official` is refused by the schema regardless
(ADR 0011), so nothing here is blocked.

## Findings

### 1. The `add` tool is arithmetic, so the tool-surface review has nothing to bite on — `info`

- **Where:** `blueprints/python-mcp-server/setup.md:75` (step 7)
- **Standard:** OWASP Top 10 for LLM Applications 2025, **excessive agency**
  (excessive functionality / excessive permissions); OWASP Top 10 for Agentic
  Applications 2026
- **What:** the single example tool adds two integers. It reads nothing, writes
  nothing, and reaches no network or filesystem.
- **Why it matters:** this is the right choice for an example and it means the
  most important review question for `project_type: agent` — what can this tool
  surface actually do on the user's behalf — cannot be answered by looking at
  this blueprint. The answer will be decided by whoever writes the second tool.
- **Fix:** none. `AGENTS.md` already tells the reader to delete `add` and write
  theirs. Recorded so the next reviewer does not raise it as an omission.

### 2. Nothing bounds how often a tool can be called — `low`

- **Where:** `blueprints/python-mcp-server/overview.md`, "What it is NOT for"
- **Standard:** OWASP API Security Top 10 2023, **API4:2023 Unrestricted
  Resource Consumption**
- **What:** no rate limiting under either transport.
- **Why it matters:** under stdio the caller is the user's own agent in the
  user's own process, so the limit is their patience — this is genuinely not a
  gap there. Over HTTP it would be, and the blueprint binds to loopback
  precisely so that it is not reachable by anybody else.
- **Fix:** already declared as absent, with that reasoning, in `overview.md`.
  Left open as a `low` because the declaration is the mitigation, not the
  control.

### 3. The interpreter version in CI is not the minimum the blueprint claims — `info`

- **Where:** `blueprints/python-mcp-server/setup.md:240` (step 12) against
  `manifest.yaml:19`
- **Standard:** NIST SSDF, build reproducibility
- **What:** `requires_tools` says `python>=3.10`; CI runs 3.13.
- **Why it matters:** a floor nobody tests is a floor nobody knows is real. The
  SDK requires 3.10 and the recipe would probably work there; "probably" is the
  word doing the work.
- **Fix:** either a CI matrix across 3.10 and 3.13, or raise the declared
  minimum to what is actually tested. Neither is urgent for a `community`
  blueprint, and both are a single-line change. Recorded rather than fixed.

## What was checked and found sound

- **The rebinding guard is proven, not asserted.** Step 18 sends
  `Origin: https://example.com` and requires `403`. This is the control the two
  hand-written MCP blueprints were missing until yesterday, and here it is both
  present and load-bearing: widening `allowed_origins` to make a client work
  breaks a step (MCP specification 2026-07-28, security best practices; OWASP
  Top 10:2025 A01).
- **The default is the safe one.** `TransportSecuritySettings` has DNS
  rebinding protection on by default, and `allowed_origins` starts empty, which
  refuses every request carrying an `Origin` header at all. A reader who copies
  this and forgets to think about origins is still protected — the opposite of
  the usual failure, where the safe configuration is the one you have to
  remember.
- **The server binds to loopback.** `host="127.0.0.1"`, not `0.0.0.0`
  (OWASP Top 10:2025 A02 Security Misconfiguration).
- **Port 0, with the reason in a comment.** A fixed port can already be taken,
  and the failure mode that matters is not "it did not start" but "you are
  talking to somebody else's server".
- **The tests speak the protocol.** `Client(create_server())` drives real MCP
  in-process. A test calling `add()` directly would pass while the tool was not
  registered at all; these would not. One of the three asserts the description
  reaches the client, which is the field a model actually depends on.
- **The stdio probe drives the process, not the object.** It catches the class
  of failure the in-process tests cannot see: an import error, a stray `print`
  corrupting the stream, an entry point that does not exist.
- **Every version pinned with `==`**, including the development set, and CI
  installs from the same file the recipe does (SSDF; SLSA v1.2 provenance).
- **Actions pinned by commit SHA** with the version in a comment
  (OWASP Top 10:2025 A03 Software Supply Chain Failures).
- **`create_server()` is a function, and the reason is written down.** Not
  style: a module-level singleton makes a fresh-server-per-test impossible and
  makes configuration read at import time.
- **Nothing writes to stdout**, and `AGENTS.md` says why twice. Under stdio
  stdout is the protocol, and this is the mistake everybody makes once.
- **No secrets, no personal data, no employer information** anywhere in the
  blueprint (CLAUDE.md §5b). The only host named is `example.com`, which
  RFC 2606 reserves for exactly this.

## Not applicable

- **Authentication and token verification (ASVS 5.0, chapters 6 and 7).** Not
  claimed. `overview.md` states plainly that a server a client launches over
  stdio inherits the user's own process, and that the reasoning stops holding
  the moment it is reachable from elsewhere — which is the sentence that makes
  this a scope decision rather than an omission.
- **BOLA / object-level authorization (API1:2023).** No objects, no users.
- **Persistence, migrations, multi-tenancy.** None claimed, all declared absent.
- **CIS Docker.** No container in this blueprint.

## Verdict

**MERGE.** Three findings, none above `low`, two of them recorded rather than
actionable. The blueprint does not repeat either fault that the hand-written MCP
blueprints carried into their own first review, which is the specific thing
worth saying about a generated one: it was written after those reviews and it
learned from them.

`tier: official` is not available to it and never will be while
`provenance: generated` (ADR 0011). `tier: verified` is available the day a
maintainer runs the setup themselves.
