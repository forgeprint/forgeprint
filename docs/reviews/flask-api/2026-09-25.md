# flask-api — architecture and security review

- Date: 2026-09-25
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due
  2026-12-21). OWASP ASVS 5.0 requirement numbers were read from the ASVS
  repository's `5.0/en` chapters on 2026-09-25. The pinned packages were
  checked against the OSV database on the same day: no known advisories.
- Reviewer: the authoring agent, following `skills/blueprint-arch-review`
- Verdict: **MERGE**

## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
It is the catalog's second Python API and the first built on Flask: a
synchronous WSGI service with an application factory, one blueprint per
resource, Flask-SQLAlchemy and Flask-Migrate on Postgres, pydantic at the
boundary and gunicorn in the image. It claims `auth`, `migrations`, `testing`,
`ci` and `containerization`, and `project_type: api`, so the checklist is the
OWASP API Security Top 10 in full, ASVS 5.0 V8 (authorization), V9
(self-contained tokens), V13 (configuration) and V16 (logging and error
handling), SSDF and SLSA for the workflow, and the image controls of the CIS
Docker Benchmark.

The single most important thing to know before building on it: **nothing
limits how often a caller may ask.** Bodies and pages are capped, but request
rate is not, and that is declared in `overview.md` rather than solved.

The authorization story is the strongest part. Authentication is a
`before_request` hook on the blueprint rather than a decorator per route, a test
walks `app.url_map` and fails when any route outside an explicit public list
answers an anonymous caller, and every notes query is built from one function
that filters on the caller. Cross-caller read, list and delete are each tested,
in-process and again against the built image.

The draft had two weaknesses found in this review and fixed before the pull
request opened. They are recorded below as resolved. No `critical` or `high`
finding is open.

The manifest claims `tier: community` and `provenance: generated`.

## Findings

### 1. Nothing limits request rate — `medium`

- **Where:** `blueprints/flask-api/setup.md:534` (step 15, `create_app`); declared
  in `overview.md`, "What it is NOT for"
- **Standard:** OWASP API Security Top 10 2023 **API4 Unrestricted Resource
  Consumption**
- **What:** any authenticated caller, and any anonymous caller of `/health` and
  `/ready`, may send as many requests as the workers accept.
- **Why it matters:** an API on the internet is called by scripts. Without a
  rate, one caller can hold every gunicorn worker (two by default) and keep the
  database busy on `/ready`.
- **Mitigating, and why this is `medium`:** the other half of API4 is covered
  and tested — request bodies are capped at 64 KiB before Flask reads them
  (`setup.md:90`, a 413 test), a page is capped at 100 items (`setup.md:233`, a
  422 test), and database connections time out after five seconds. The gap is
  named in `overview.md` with the two usual answers.
- **Fix:** left open on purpose. The right limit depends on the API and on
  whether a proxy in front already enforces one; Flask-Limiter or the reverse
  proxy are both correct.

### 2. Responses carried neither `nosniff` nor `no-store` — `medium`, resolved before the pull request

- **Where:** `blueprints/flask-api/setup.md:570` and `:576` (step 15,
  `_response_headers`)
- **Standard:** OWASP ASVS 5.0 **3.4.4** (every response carries
  `X-Content-Type-Options: nosniff`) and **14.3.2** (`Cache-Control: no-store`
  so sensitive data is not cached)
- **What:** the draft answered with Flask's defaults: a JSON body, a correct
  `Content-Type`, and no instruction to browsers or caches.
- **Why it matters:** a caller's notes are exactly the data 14.3.2 is about,
  and a shared cache in front of an API is an ordinary deployment. Without
  `nosniff`, a browser may treat a crafted JSON response as something it
  renders.
- **Resolution:** `create_app` registers an `after_request` that sets both
  headers on every response, errors included.
  `test_every_response_is_nosniff_and_no_store` checks a public route, a 404
  and a 401.

### 3. A refused token left no trace but a 401 in the access log — `low`, resolved before the pull request

- **Where:** `blueprints/flask-api/setup.md:382` (step 12, `_refuse`)
- **Standard:** OWASP ASVS 5.0 **16.3.1** (authentication operations are
  logged, including unsuccessful ones); OWASP Top 10:2025 **A09 Security
  Logging and Alerting Failures**
- **What:** the draft raised 401 without logging. gunicorn's access log showed
  the status, but not whether the token was expired, forged, for another
  audience, or absent.
- **Why it matters:** "somebody is presenting tokens signed with the wrong
  key" and "a client's clock is off" look identical in an access log and call
  for opposite responses.
- **Resolution:** every refusal logs a warning with the method, the path and
  the reason (the PyJWT exception class, or "no bearer token"), and never the
  token, which is a credential until it expires.
  `test_a_refusal_is_logged_with_its_reason_and_without_the_token` checks both
  halves.

### 4. A caller probing other callers' notes is not logged — `low`

- **Where:** `blueprints/flask-api/setup.md:488` (step 14, `_one`)
- **Standard:** OWASP ASVS 5.0 **16.3.2** (failed authorization attempts are
  logged)
- **What:** a note that exists but belongs to someone else answers 404 through
  the same query as a note that does not exist, so nothing distinguishes an
  enumeration attempt in the logs.
- **Why it matters:** walking ids is how BOLA is probed. The control holds
  (the attempt fails), but it fails silently.
- **Fix:** left open. Telling the two cases apart needs a second, unscoped
  query on every miss, which is the very query the design keeps out of the
  code. A 404 rate per caller at the proxy detects the same pattern without it.
  Recorded so the choice is visible.

### 5. Transitive dependencies are not pinned — `low`

- **Where:** `blueprints/flask-api/setup.md:23` (step 3, `requirements.txt`)
- **Standard:** OWASP Top 10:2025 **A03 Software Supply Chain Failures**; NIST
  SSDF **PS.3** (archive and protect each software release)
- **What:** the nine direct dependencies are pinned with `==`; Werkzeug,
  Jinja2, click, pydantic-core and the rest resolve to whatever is newest and
  compatible on the day of the install, without hashes.
- **Why it matters:** two builds of the same commit can differ, and a
  compromised transitive release would be picked up without a change in the
  repository.
- **Fix:** left open, consistent with the catalog's other Python blueprints.
  The step up is a lock file with hashes (`pip-compile --generate-hashes` or
  `uv pip compile`), which the reader adopts together with the tool that
  maintains it.

### 6. Tokens are not checked for type or issuer — `info`

- **Where:** `blueprints/flask-api/setup.md:403` (step 12, `jwt.decode`)
- **Standard:** OWASP ASVS 5.0 **9.2.2** (a token is the correct type for its
  purpose) and **9.1.3** (key material comes from trusted, pre-configured
  sources)
- **What:** the audience, expiry and subject are required; `typ` and `iss` are
  not checked.
- **Why this is `info`:** with one shared HS256 key, the key is the issuer —
  nothing that lacks it can mint a token this service accepts, and 9.1.3 is met
  because the key comes from configuration, never from a token header. The
  moment tokens come from an identity provider with its own keys, the issuer
  and the access-token type (`at+jwt`, RFC 9068) become the controls that
  separate this service's tokens from the provider's others. `overview.md`
  names that change and where it goes.

### 7. The base image is pinned to a patch tag, not a digest — `info`

- **Where:** `blueprints/flask-api/setup.md:1126` and `:1132` (step 28)
- **Standard:** CIS Docker Benchmark v1.8.0, image and Dockerfile scope
  (trusted, pinned base images); SLSA v1.2 build track
- **What:** `python:3.13.15-slim` moves when Debian patches land under the
  same tag.
- **Why this is `info`:** a digest is byte-exact and also stops security
  patches arriving. The tag is the patch release, so a Python upgrade is still a
  reviewed change. `overview.md` states the trade-off.

## What was checked and found sound

- **Object-level authorization (API1:2023, ASVS 8.2.2).** Every notes query
  starts from `owned()` (`setup.md:484`), and another caller's note is 404 —
  indistinguishable from one that does not exist. Tested for read, list and
  delete in-process, and read again through gunicorn against Postgres (steps
  49–50).
- **Authentication of every non-public route (API2:2023, ASVS 8.3.1).**
  Protection is blueprint membership, not a decorator. The url-map test
  enumerates every rule and method, so a new route is covered without anyone
  remembering to add a test.
- **Token validation (ASVS 9.1.1, 9.1.2, 9.2.1, 9.2.3).** A MAC is verified
  with an allowlist of one algorithm; `exp`, `sub` and `aud` are required;
  `nbf` is honoured when present. Tests forge a token with another key, for
  another audience, expired, with no expiry, and unsigned (`alg: none`).
- **Mass assignment (API3:2023).** `extra="forbid"` on the input model; a body
  naming `owner` is 422 with a pointer to the field, and the response model
  does not echo the owner.
- **Configuration and secrets (Twelve-Factor III, ASVS 13.3.1, CLAUDE.md
  §5b).** One reader of the environment. Unset `APP_ENV` is production, which
  refuses a missing, placeholder or short key before gunicorn serves — proved
  against the built image in step 52. The key used by the recipe is generated
  per run into a file both ignore files exclude. Every example value carries
  `local-development-only` or `not-a-real-secret`, and production refuses the
  latter by substring.
- **Error handling (Top 10:2025 A10, ASVS 16.5.1, 16.5.4).** One module turns
  400, 401, 404, 405, 413, 415, 422 and 500 into RFC 9457 documents; routing
  redirects are left alone by Flask before the handler runs. The last-resort
  handler logs the traceback and tells the caller nothing, tested with an
  exception whose message contains a password.
- **Failed dependencies (ASVS 16.5.2).** `/health` touches nothing and backs
  the container `HEALTHCHECK`; `/ready` answers 503 when the database is
  unreachable, tested with an address nothing listens on, while `/health`
  stays 200.
- **Debug off in production (ASVS 13.4.2).** The image runs gunicorn; Flask's
  debugger exists only behind `flask run --debug`, which the recipe mentions
  for development.
- **Migrations.** Generated against Postgres, applied from the image as a
  separate one-off rather than at worker start, checked for drift by a test,
  and run down and up on the test database every run. The tests refuse a
  database whose name does not end in `_test`, because they empty it.
- **Container (CIS Docker, image scope).** Multi-stage build, UID 10001,
  `HEALTHCHECK`, no build tools or tests in the runtime stage, `.dockerignore`
  excluding the key, tokens and `.git`. The compose service adds a read-only
  root filesystem, all capabilities dropped and `no-new-privileges`.
- **CI (SSDF PS.1, SLSA v1.2).** Actions pinned by commit SHA,
  `permissions: contents: read`, `persist-credentials: false`, tests against a
  Postgres service, the formatter and linter as gates, and the image built.
- **Boundaries.** `app/extensions.py` holds the unbound extensions so models
  and blueprints never import the factory; nothing is built at import time.
  There is no domain layer to violate — the blueprint does not claim one, and
  `AGENTS.md` describes the shape it does have.

## Not applicable

- **API5 Broken Function Level Authorization, ASVS 8.2.1.** There is one role;
  every authenticated caller may call every route on their own data.
- **API6 Unrestricted Access to Sensitive Business Flows.** No business flow.
- **API7 SSRF.** The service makes no outbound request.
- **API10 Unsafe Consumption of APIs.** No upstream API is consumed.
- **ASVS 3.4.1 (HSTS), 3.4.3 (CSP), 4.1.2 (HTTPS redirects).** TLS is
  terminated in front of the service, which does not choose that layer; CSP
  governs documents a browser renders, and this API renders none.
- **ASVS 3.4.2 (CORS).** No `Access-Control-*` header is sent, so no origin is
  allowed; `overview.md` says so.
- **ASVS V6 and V7 (passwords, sessions).** No passwords, no cookies, no
  sessions; Flask's `SECRET_KEY` is never set because nothing signs a cookie.
- **OWASP LLM and Agentic Top 10, MCP guidance.** Not an agent.
- **CIS Docker daemon and host controls.** The reader's environment, not the
  blueprint's.
