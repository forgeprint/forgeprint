# go-http-service — architecture and security review

- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due

## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
The catalog's fourth `api` and its first in Go.

This one was written after the .NET and Python API blueprints had already been
reviewed, and it does not repeat their faults: configuration fails closed at
startup rather than per request, and the unauthenticated request is proved
refused rather than assumed. Where it is weaker than `dotnet-web-api` is
structural and the blueprint says so — Gin has no equivalent of ASP.NET Core's
fallback authorization policy, so "protected" is a property of which group a
route is declared in, and nothing in the framework catches a route declared
outside it.

The manifest claims `tier: community` and `provenance: generated`.

## Findings

### 1. A route declared outside the group is public, and only a test would notice — `medium`

- **Where:** `blueprints/go-http-service/setup.md:118` (step 5)
- **Standard:** OWASP API Security Top 10 2023, **API5:2023 Broken Function
  Level Authorization**; OWASP Top 10:2025 **A01 Broken Access Control**
- **What:** authentication is applied by `router.Group("/",
auth.RequireBearer(settings))`. Any handler registered on `router` instead of
  on `protected` is reachable without a token.
- **Why it matters:** this is the same failure class the two .NET blueprints
  were fixed for, and Gin offers no framework-level defence — there is no
  fallback policy to set. The next person adding a status endpoint in a hurry
  types `router.GET` because that is what the `/health` line above it does.
- **Mitigating, and why this is `medium` rather than `high`:** the rule is
  stated twice in `AGENTS.md`, the `/health` exception carries its reason in a
  comment, and **the container check asserts the 401** — so the specific route
  that exists is proved, and a reader is told the rule. What is absent is
  enforcement, and no amount of documentation is enforcement.
- **Fix:** a test that walks `router.Routes()` and fails on any path outside an
  allow-list that lacks the middleware. Gin exposes the route table, so this is
  a dozen lines and it converts a convention into a check. Worth doing before
  this blueprint gains a second protected route.

### 2. Nothing bounds how often a route can be called — `low`

- **Where:** `blueprints/go-http-service/overview.md`, "What it is NOT for"
- **Standard:** OWASP API Security Top 10 2023, **API4:2023 Unrestricted
  Resource Consumption**
- **What:** no rate limiting.
- **Why it matters:** a legitimate scope decision for a service behind a
  gateway, and a real gap for one exposed directly.
- **Fix:** already declared as absent, with that distinction stated. Left open
  because the declaration is the mitigation, not the control.

### 3. HMAC means the verifier holds the signing key — `low`

- **Where:** `blueprints/go-http-service/setup.md:62` (step 4)
- **Standard:** OWASP ASVS 5.0, Cryptography chapter; OWASP API2:2023
- **What:** HS256 with a shared secret. `WithValidMethods(["HS256"])` correctly
  prevents algorithm confusion, and the secret that verifies is the secret that
  signs.
- **Why it matters:** anything that can verify a token can mint one. For an
  internal service behind a single issuer that is normal; the moment a third
  party issues tokens it is wrong, and the change to RS256 or JWKS is not a
  one-line edit.
- **Fix:** stated in `overview.md` under Cons. Recorded so the next reviewer
  does not raise it as an oversight.

### 4. The Go floor is set by a dependency, and the recipe now says so — `info`

- **Where:** `blueprints/go-http-service/setup.md:16` (step 2) and `:398`
  (step 14)
- **Standard:** NIST SSDF, build reproducibility
- **What:** `go mod init` writes the author's installed toolchain into `go.mod`,
  and `go get` raises the floor when a dependency demands it — gin 1.12
  requires 1.25.
- **Why it matters:** the mismatch between that floor and the pinned builder
  image surfaces inside Docker as `go.mod requires go >= 1.25.0`, which reads
  like a network failure. It happened while building this blueprint.
- **Fix:** already done, and it is the interesting part: step 2 sets the floor
  explicitly rather than inheriting it, and step 14 compares it against the
  Dockerfile. The failure is now a step that fails on the author's machine.

## What was checked and found sound

- **The unauthenticated request is proved refused twice** — in `httptest` and
  again against the running container. Either alone could pass for the wrong
  reason; together they cover the routing and the deployed image.
- **A forged token is tested.** A token signed with a different secret is
  refused, which is the test that fails the day verification is reduced to
  decoding (OWASP API2:2023).
- **Every `jwt.Parse` option is present and explained**: `WithValidMethods`
  (algorithm confusion), `WithAudience` (a token for another service),
  `WithIssuer`, `WithExpirationRequired` (a token valid forever). Removing any
  one leaves code that still looks correct — which is why they are annotated
  rather than merely present.
- **401, not 403**, with the distinction written down.
- **The rejection reason is not returned to the caller**, which is right: which
  check failed helps an attacker and nobody else.
- **Configuration fails closed at startup.** `log.Fatalf` before anything
  listens, not a check inside a handler — the fault both .NET blueprints and
  `fastapi-service` had to be fixed for (OWASP Top 10:2025 A10).
- **`/health` touches nothing** and says why, so it keeps answering when a
  dependency is down (OWASP A09; Twelve-Factor IX).
- **`ReadHeaderTimeout` is set**, which is the defence against a client holding
  a connection open by sending headers one byte at a time — absent from most
  Go examples.
- **Distroless, non-root, `CGO_ENABLED=0`, `-trimpath`**, no tests or Dockerfile
  in the image (CIS Docker image scope), and the recipe runs the image rather
  than trusting the build.
- **`go.sum` gives hash-level verification** on every later build — stronger
  than the version pinning the rest of the catalog relies on.
- **`go vet` in the recipe and in CI**; **actions pinned by commit SHA**
  (OWASP Top 10:2025 A03).
- **No secrets, no personal data, no employer information** (CLAUDE.md §5b).
  The only values that look like credentials are labelled
  `local-development-only-not-a-real-secret` and `not-a-real-secret-only-for-tests`.

## Not applicable

- **BOLA / object-level authorization (API1:2023).** No objects and no owner;
  `/items` returns an empty list to prove the group is wired.
- **Multi-tenancy.** Not claimed; `overview.md` points at
  `dotnet-multitenant-saas-api` for that.
- **Migrations, connection pooling, transaction boundaries.** No database, and
  `overview.md` says the interesting decisions are still ahead of the reader.
- **Token issuance, password storage, session management (ASVS 5.0).** Verifies
  only.
- **OWASP LLM 2025 and Agentic 2026.** `project_type: api`.
- **CIS Docker host and daemon controls.** A blueprint does not configure the
  reader's daemon.

---

## Verdict

**MERGE.** One `medium`, two `low`, one `info`.

The `medium` is worth acting on and is not a blocker: the rule is documented,
the exception is explained, and the one protected route that exists is proved
refused. What is missing is enforcement, and the fix — a test over
`router.Routes()` — is a dozen lines. It belongs in the change that adds this
blueprint's second protected route, whenever that is.

`tier: official` is not available while `provenance: generated` (ADR 0011).
