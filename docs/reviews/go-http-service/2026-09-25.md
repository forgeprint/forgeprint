- Date: 2026-09-25
- Blueprint version: 1.2.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due
  2026-12-21), and the checklists of the Go experts proposed in #90
  (`go-senior-architect`) and #93 (`go-backend-engineer`), whose references

- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Verdict: **MERGE**

## Summary

A re-review of the change that closes three findings the Go experts raised
against 1.1.0: no graceful shutdown, an error compared with `!=`, and a Go
floor that no longer gets security fixes. All three are closed, and each is
closed by something that fails when it regresses — a unit test and a
container step for the shutdown, a linter for the comparison, and the existing
floor-versus-image check for the toolchain.

The single most important thing for a reader: the drain is eight seconds and
is sized to fit inside `docker stop`'s ten and Kubernetes' thirty. Whoever
changes one of those numbers has to change the other.

The manifest still claims `tier: community` and `provenance: generated`.

## Findings closed by this change

### A. The server did not drain on SIGTERM — `medium`, closed

- **Where:** `blueprints/go-http-service/setup.md:256` (step 7,
  `internal/server/server.go`), `:544` (step 9, `main.go`), `:407` and `:458`
  (step 8, the tests), `:703` (step 27)
- **Standard:** `go-backend-engineer` GL4 and GL5 (Go 1.27 `os/signal`
  `NotifyContext`, `net/http` `Server.Shutdown`; Kubernetes 1.37 pod
  termination); The Twelve-Factor App, IX Disposability
- **What it was:** `main` called `ListenAndServe` and nothing else, so SIGTERM
  killed the process with requests in flight.
- **What it is now:** `main` derives its context from
  `signal.NotifyContext(..., SIGTERM, SIGINT)`. `server.Run` serves on an
  injected listener and, when the context is done, calls `Shutdown` with a
  fresh context bounded by `ShutdownTimeout` (8 s) — derived with
  `context.WithoutCancel`, because the cancelled parent would give the drain no
  time. Past the deadline it calls `Close` and returns the deadline error.
- **Proof:** `TestShutdownFinishesTheRequestInFlightAndRefusesNewOnes` holds a
  request in its handler, cancels, and asserts in order that a new connection
  is refused, that `Run` has not returned, that the held request completes
  with 200, and that `Run` then returns nil. `TestShutdownGivesUpAtItsDeadline`
  asserts `errors.Is(err, context.DeadlineExceeded)` with a request that never
  finishes. Step 27 stops the real container and reads its exit code, because
  `docker stop` itself exits 0 even when it had to SIGKILL; 0 is only possible
  if the binary handled SIGTERM and returned from `main`.
- **Checked alongside:** the binary is `ENTRYPOINT` in exec form on distroless,
  so it is PID 1 with no shell in front to swallow the signal. A Go process as
  PID 1 receives SIGTERM because it registers a handler for it.
  `ReadHeaderTimeout` is kept, and moved with the server into
  `internal/server`.

### B. An error was compared with `!=` — `low`, closed

- **Where:** `blueprints/go-http-service/setup.md:319` (step 7), `:679`
  (step 19), `:632`–`:638` (step 13, the generated CI)
- **Standard:** `go-backend-engineer` EW2 (Go 1.27 package `errors`);
  golangci-lint 2.14 `errorlint`
- **What it was:** `err != http.ErrServerClosed` after `ListenAndServe`.
- **What it is now:** `errors.Is(err, http.ErrServerClosed)`, on the value
  `Serve` sends through a channel. The rest of the generated code was read for
  other comparisons against an error value: `auth.go`, `api.go`, `main.go` and
  both test files compare errors only against `nil`, and the new test matches
  the deadline with `errors.Is`.
- **Gate:** step 19 runs
  `go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.14.0 run --enable-only errorlint ./...`.
  v2.14.0 is the latest on the module proxy (released 2026-09-24); its module
  requires Go 1.26, so the 1.27 toolchain builds it. It comes from
  `proxy.golang.org`, which `lint-setup` allows, and `go run pkg@version`
  leaves `go.mod` untouched. The generated CI runs the same line.

### C. Go 1.25 no longer gets security fixes — `medium`, closed

- **Where:** `blueprints/go-http-service/setup.md:16` (step 2), `:580`
  (step 11), `:634` (step 13); `manifest.yaml` `requires_tools`
- **Standard:** Go release policy — the two newest minors are supported, and
  go.dev lists 1.27.1 and 1.26.8 on 2026-09-25 (`go-backend-engineer`
  references); NIST SSDF v1.1, respond to vulnerabilities. A statically linked
  Go binary carries the standard library it was built with, so `net/http`
  fixes that 1.25 no longer receives would ship in the image.
- **What it is now:** `go 1.27` in `go.mod`, `go>=1.27` in `requires_tools`,
  `golang:1.27.1-alpine` as the builder (verified on Docker Hub), and
  `go-version: '1.27.1'` in the generated CI. Step 16's floor-versus-image check
  now reads the minor out of a patch-level tag and still compares `1.27` with
  `1.27`.
- **Other pins, re-read on 2026-09-25:** gin v1.12.0 and golang-jwt v5.3.1 are
  the latest on the proxy and did not move. `actions/setup-go` moved from
  v5.5.0 (node20) to v7.0.0 (node24), pinned by commit SHA.
  `actions/checkout` v5.0.0 already runs on node24 and did not move.
  `gcr.io/distroless/static-debian12:nonroot` is still published.

## Open findings

### 1. `ReadTimeout`, `WriteTimeout` and `IdleTimeout` are still zero — `low`

- **Where:** `blueprints/go-http-service/setup.md:285` (step 7)
- **Standard:** `go-backend-engineer` ST2 (Go 1.27 `net/http` `Server`: a zero
  timeout means none); OWASP API Security Top 10 2023, API4:2023 Unrestricted
  Resource Consumption
- **What:** only `ReadHeaderTimeout` is set. A client that sends headers
  promptly and then trickles the body, or never reads the response, holds a
  goroutine and a connection with no bound.
- **Why `low`:** there is no route that reads a body, and every response is a
  few bytes. It becomes `medium` the day a handler accepts a request body.
- **Fix:** set all three in `server.New` (for example 10 s, 10 s, 60 s), with
  `WriteTimeout` above the slowest handler. The shutdown test is unaffected as
  long as the held request stays under `WriteTimeout`.

### 2. Nothing turns unready before the drain — `low`

- **Where:** `blueprints/go-http-service/overview.md`, "What it is NOT for"
- **Standard:** `go-backend-engineer` GL5 and GL7 (Kubernetes 1.37 pod
  lifecycle and container probes)
- **What:** there is a liveness endpoint and no readiness endpoint, so the
  first signal a load balancer gets is refused connections.
- **Fix:** declared in `overview.md`. A `/readyz` that turns 503 when the
  context is cancelled belongs in the change that adds a dependency worth
  checking.

### 3. errorlint allow-lists the original line — `info`

- **Where:** `blueprints/go-http-service/setup.md:679` (step 19)
- **Standard:** golangci-lint 2.14 `errorlint`
- **What:** errorlint does not report a comparison made directly on the
  return of `ListenAndServe` or `Serve`, because the standard library
  documents `ErrServerClosed` as returned unwrapped. So the gate would not
  have caught finding B in its original form. It does report the comparison
  where it now sits, on a value received from a channel, and it reports every
  comparison against a sentinel of the project's own. Both were checked
  against v2.14.0 on 2026-09-25.
- **Fix:** none needed; recorded so the next reviewer does not assume the
  linter covers more than it does.

### 4. Carried from 2026-09-23

- **Rate limiting absent — `low`.** Unchanged, and declared (OWASP API4:2023).
- **HMAC means the verifier holds the signing key — `low`.** Unchanged, and
  declared (OWASP API2:2023).

## What was checked and found sound

- **The drain order is right.** `Shutdown` closes listeners before it waits,
  and the test asserts the refusal while the held request is still running,
  not after — the order is observed rather than read from the documentation.
- **No goroutine is left without an owner** (`go-backend-engineer` GL1, GL3).
  The one `Run` starts sends to a buffered channel, so it exits whether or not
  anybody receives; on the deadline path `Close` makes `Serve` return.
- **The drain deadline is below every grace period it has to fit inside** —
  8 s against `docker stop`'s 10 s and Kubernetes' 30 s — and the reason is
  written beside the constant.
- **The shutdown path is `errors.Join`ed**, so a `Close` error is not lost
  behind the deadline error, and `errors.Is` still finds the deadline.
- **`go vet ./...` runs in full** in the recipe and in CI (`go-senior-architect`
  TG3), and the errorlint step is pinned (TG1's intent, without adding a
  `tool` directive to a template's `go.mod`).
- **Everything the 2026-09-23 review found sound still holds**: the four
  `jwt.Parse` options, 401 rather than 403, the rejection reason withheld,
  configuration failing closed before anything listens, distroless and
  non-root, actions pinned by commit SHA, `permissions: contents: read`.
- **No secrets, no personal data, no employer information** (CLAUDE.md §5b).
  The only credential-shaped values are still
  `local-development-only-not-a-real-secret` and
  `not-a-real-secret-only-for-tests`.

## Not applicable

- **staticcheck, govulncheck and the race detector** (`go-senior-architect`
  TG4–TG6). Worth adding and not part of these three findings; a template that
  gains them should do so in one change with their pins.
- **goleak and the `goroutineleak` profile** (`go-backend-engineer` GL9,
  GL10). The only goroutine is `Serve`'s, and its exit is asserted by the
  shutdown test returning.
- **Database pool shutdown ordering** (GL5's last clause). No database.
- **CIS Docker host and daemon controls.** A blueprint does not configure the
  reader's daemon.
