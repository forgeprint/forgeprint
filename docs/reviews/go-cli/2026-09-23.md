## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
The third `cli` blueprint and the catalog's first Go anything.

Most of the security checklist is inapplicable, as with the other two, and is
listed below rather than left to assumption. What is specific to this one is
that it **disagrees with the framework's own scaffolding**, and the review's
job is to say whether that disagreement is justified. It is: `cobra-cli init`
generates a package-level `rootCmd` whose flags live in package-level
variables, and that is a shared-state bug waiting for the second test.

The manifest claims `tier: community` and `provenance: generated`.

## Findings

### 1. `go.sum` is generated by the recipe rather than shipped — `low`

- **Where:** `blueprints/go-cli/setup.md:236` (step 10)
- **Standard:** OWASP Top 10:2025 **A03 Software Supply Chain Failures**;
  SLSA v1.2
- **What:** step 2 pins Cobra to `v1.10.2` and step 10 runs `go mod tidy`,
  which writes `go.sum` with the hashes of what it resolved at that moment.
- **Why it matters:** this is stronger than what the rest of the catalog does —
  Go verifies every module against `go.sum` on every build, so once the file
  exists the dependency graph is pinned by hash, not just by version. The
  finding is that the file is produced at setup time rather than reviewed:
  whoever runs the recipe gets whatever the proxy served that day, and nothing
  tells them to look at it.
- **Fix:** a sentence in `AGENTS.md` saying `go.sum` is a security artefact and
  belongs in the first commit, read rather than regenerated. Not a defect;
  recorded because it is the one place this blueprint is ahead of the others
  and could be further ahead cheaply.

### 2. Arguments are counted but not validated — `low`

- **Where:** `blueprints/go-cli/setup.md:96` (step 4)
- **Standard:** OWASP ASVS 5.0, Validation chapter
- **What:** `cobra.ExactArgs(1)` guarantees there is one argument; nothing
  checks what it contains before it goes into a string.
- **Why it matters:** the same finding as in `node-cli` and `python-cli`, for
  the same reason: the next command takes a path or a URL, and the example is
  what the reader copies.
- **Fix:** none at this scope. `cobra.MatchAll` and a custom `Args` function
  are the idiomatic answer and belong in the command that needs them.

### 3. The module path is a placeholder that must change — `info`

- **Where:** `blueprints/go-cli/setup.md:16` (step 1)
- **Standard:** none; a usability observation
- **What:** `example.com/example-cli`. Go module paths appear in every import
  in the repository, so renaming later touches every file.
- **Why it matters:** it is the one thing in this recipe that is expensive to
  postpone, unlike a package name in the other two CLI blueprints.
- **Fix:** already said in `AGENTS.md`, under "What this does not do". Recorded
  so a reviewer does not treat it as an oversight.

## What was checked and found sound

- **`NewRootCommand` is a constructor taking an `io.Writer`.** This is the
  blueprint's central claim and it holds: a package-level `rootCmd` — what the
  official scaffolding generates — keeps flag values in package-level
  variables, so a second test in the same run inherits the first one's
  `--shout`. Every test here builds a fresh tree against a buffer. The
  disagreement with the framework's own generator is deliberate, explained
  where it happens, and correct.
- **`SilenceUsage` and `SilenceErrors` are both set**, so a returned error is
  reported once, on stderr, by `main` — rather than followed by two screens of
  help text, which is what the Cobra defaults produce and why so many Go tools
  behave that way.
- **`Args: cobra.ExactArgs(1)` is declared**, which is what turns a missing
  argument into a message rather than a panic on `args[0]`.
- **`main` owns the exit code** and nothing else does. `RunE` returns; `main`
  prints and exits. That split is what makes the tool both script-callable and
  testable without a subprocess.
- **`go vet` runs in the recipe and in CI** (OWASP Top 10:2025 A10 —
  mishandling of exceptional conditions is exactly what `vet` finds).
- **Cobra pinned to an exact version**, and `go.sum` gives hash verification on
  every subsequent build — stronger than the version pinning the rest of the
  catalog relies on.
- **Actions pinned by commit SHA** with the version in a comment (A03).
- **The recipe checks what a user sees**: runs the tool, reads the output,
  reads `--help` for the command name, asserts a bad invocation is non-zero.
- **No secrets, no personal data, no employer information** (CLAUDE.md §5b).
  The only host named is `example.com`, which RFC 2606 reserves.

## Verdict

**MERGE.** Two `low` findings and one `info`, none blocking.

The one worth reading is the first, and it is unusual: the finding is not that
the supply-chain handling is weak but that it is the strongest in the catalog
and one sentence away from being stronger still. `go.sum` is a security
artefact, and nothing currently tells the reader to treat it as one.

`tier: official` is not available while `provenance: generated` (ADR 0011).
