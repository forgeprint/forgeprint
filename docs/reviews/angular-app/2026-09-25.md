# angular-app — architecture and security review

- Date: 2026-09-25
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 and 2026-09-23
  (next re-check due 2026-12-21)
- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Verdict: **MERGE**

## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
An Angular 22 single-page application that talks to an API it does not own,
built the way Angular now recommends starting one: standalone, zoneless,
signals for state. It claims `testing`, `i18n` and `ci`, and each claim is
backed by something that fails when the claim stops being true.

The one thing a reader should know before building on it: the browser-side
security is escaping and a narrow network boundary, not headers. There is no
Content-Security-Policy, because a static build does not set response headers;
the blueprint now says so in `overview.md` and `AGENTS.md`.

The manifest claims `tier: community` and `provenance: generated`. No
`critical` or `high` finding is open.

## Findings

### 1. No Content-Security-Policy or other security headers — `medium`

- **Where:** `blueprints/angular-app/setup.md` step 7 (`angular.json`, no
  `security` block) and the generated `src/index.html`
- **Standard:** OWASP Top 10:2025 **A02 Security Misconfiguration**; OWASP ASVS
  5.0 chapter V3 (web frontend security: browser security mechanisms)
- **What:** the build emits static files with no CSP meta tag, and the recipe
  configures no host, so nothing sets CSP, HSTS, `frame-ancestors` or
  `X-Content-Type-Options`.
- **Why it matters:** CSP is the control that limits the damage of an XSS bug
  somebody adds later. Without it, the only defence is Angular's escaping.
- **Mitigating, and why this is `medium` rather than `high`:** there is no
  injection sink in the project. API text is rendered with interpolation
  (`{{ note.body }}`, step 12), which Angular escapes; there is no
  `[innerHTML]`, no `bypassSecurityTrust*` and no third-party script. Headers
  are the host's decision, and the gap is disclosed: `overview.md` lists
  "Security headers and error reporting" under what it is not for, and
  `AGENTS.md` names interpolation as the defence actually in place and asks for
  a review reason before `[innerHTML]` or `bypassSecurityTrust*` appears.
- **Fix:** none to the recipe. A reader deploying it sets CSP at the host, or
  evaluates Angular's build-time CSP generation for the inline bootstrap
  script.

### 2. The i18n claim is message translation only — `low`

- **Where:** `blueprints/angular-app/manifest.yaml` (`requirements: [i18n]`);
  `setup.md` steps 7, 19, 29, 36 and 37
- **Standard:** review-standards "How a reference is used" — a claim is judged
  by what verifies it; the same rule the review skill applies to
  `accessibility`
- **What:** the recipe proves compile-time translation (the en-GB bundle
  carries `Organise`, the en-US one does not), completeness (a missing
  translation fails the build; CI compares message counts) and a `lang`
  attribute per locale. It does not demonstrate ICU plural or select
  messages, right-to-left layout, or locale-aware formatting.
- **Why it matters:** `resolve` matches on the word `i18n`. Somebody who needs
  Arabic or Hebrew layout, or plural rules, gets the mechanism and not the
  hard part.
- **Fix:** disclosed in `overview.md` ("More i18n than message translation").
  Nothing further for 1.0.0.

### 3. Uncaught errors go to the console only — `low`

- **Where:** `setup.md` step 16 (`provideBrowserGlobalErrorListeners()`)
- **Standard:** OWASP Top 10:2025 **A09 Security Logging and Alerting
  Failures**
- **What:** global errors reach Angular's default `ErrorHandler`, which logs
  them in the user's browser. Nothing is reported anywhere an operator could
  see it.
- **Why it matters:** a failure in production is invisible unless a user
  reports it.
- **Mitigating:** request failures are handled and shown (finding-free, see
  below), and adding a reporting service means choosing a vendor, which a
  blueprint with no account anywhere should not do. Disclosed in
  `overview.md`.
- **Fix:** none for 1.0.0; a custom `ErrorHandler` provider is the seam.

### 4. The scaffolder's own dependency tree is not locked — `low`

- **Where:** `setup.md` step 1 (`npx --yes @angular/cli@22.2.0 new ...`)
- **Standard:** OWASP Top 10:2025 **A03 Software Supply Chain Failures**; NIST
  SSDF PW.4 (reuse well-secured software)
- **What:** the CLI version is exact, but `npx` resolves the CLI's transitive
  dependencies from ranges on the day it runs, and runs their install scripts.
- **Why it matters:** the generator is the one piece of the recipe not covered
  by a lock file.
- **Mitigating:** it runs once, `--skip-install` keeps it from installing the
  project, and step 2 replaces `package.json` with exact versions before
  anything the project depends on is installed; from then on
  `package-lock.json` (with integrity hashes) is what CI installs from.
- **Fix:** none. Recorded so the difference between "the generator is pinned"
  and "the generator's tree is locked" is written down.

### 5. The generated CI workflow is least-privilege — `info`

- **Where:** `setup.md` step 24 (`.github/workflows/ci.yml`)
- **Standard:** SLSA v1.2 build track; NIST SSDF PS.1 (protect code from
  unauthorized access and tampering)
- **What:** `permissions: contents: read`, `persist-credentials: false` on
  checkout, both actions pinned to a full commit SHA (checkout v7.0.1,
  setup-node v7.0.0, SHAs read from the action repositories on 2026-09-25),
  and `npm ci` from the committed lock file.
- **Why it matters:** this is the correct shape and worth recording as such.

## What was checked and found sound

- **One network boundary, enforced three ways.** Every request goes through
  `HttpClient` and `apiInterceptor` (step 9). The interceptor refuses absolute
  URLs, protocol-relative URLs, `data:` URLs and `..` in its plain, percent
  encoded and backslash spellings before a request is created — the spellings
  the WHATWG URL parser resolves alike. Tests assert each refusal and that
  nothing reached the testing backend (`HttpTestingController.verify()`), and
  removing the `..` check was tried and fails the three tests that spell it. Lint refuses the
  `fetch` and `XMLHttpRequest` globals and `HttpClient` in a component. OWASP
  Top 10:2025 A01 (SSRF-shaped misuse from the client is absorbed there).
- **A deadline on every request** — 10 seconds, applied in the interceptor, and
  a test with fake timers proves the caller gets a `TimeoutError` and the
  request is cancelled. OWASP Top 10:2025 **A10 Mishandling of Exceptional
  Conditions**.
- **Failure is visible and loses nothing.** A failed or malformed load sets an
  `error` status rendered as `role="alert"`; a failed save keeps the draft. Both
  are tested. OWASP A10.
- **Responses are validated before they are typed.** `parseNotes` and
  `parseNote` check the shape; a wrong-shaped response becomes an error state,
  tested. OWASP ASVS 5.0 V1 (encoding and sanitization) / V2 (validation and
  business logic) — input from the API is untrusted input.
- **Output encoding.** API text is rendered only through interpolation; there
  is no `[innerHTML]` and no sanitizer bypass anywhere in the recipe. OWASP
  Top 10:2025 A05 Injection.
- **Cross-site request forgery.** `provideHttpClient` keeps Angular's default
  XSRF handling: for mutating requests to a relative URL it copies the
  `XSRF-TOKEN` cookie into a header, and the interceptor keeps the default
  base URL relative, so the POST in the store qualifies. Whether the API issues
  that cookie is the API's decision. OWASP ASVS 5.0 V3.
- **Configuration.** One value, `API_BASE_URL`, in one place, defaulting to a
  same-origin path, so no URL is baked into the bundle and there is no CORS
  policy to get wrong. There are no secrets in a browser bundle to leak, and
  the recipe introduces none. Twelve-Factor III, applied as far as a static
  build allows; the trade-off is written in `overview.md`.
- **Dependencies pinned and minimal.** Every version in `package.json` is
  exact and was read from the registry on 2026-09-25; `@angular/forms` and
  `zone.js` are not installed because nothing uses them. OWASP A03.
- **No source maps in production**, asserted by step 39.
- **Boundaries.** Pages depend on stores; stores depend on `HttpClient`; only
  `core/api.ts` knows where the API is. The dependency direction is enforced by
  lint rather than by folder names. Hexagonal architecture (ports and
  adapters): the interceptor and the parsers are the adapter edge.
- **The lazy boundary is real.** Step 38 asserts the notes feature's text is in
  a separate chunk and not in `main`, and the 350 kB initial budget is proved
  to fail the build (steps 30–33) rather than assumed to.
- **Test strategy proves the claims.** 21 tests across the interceptor, the
  store, the guard and the real routes through `RouterTestingHarness`; removing
  the guard from the route was tried and fails the route test.
- **Decisions are recorded where they can be disagreed with**: `overview.md`
  "Trade-offs made on your behalf" and the CHANGELOG. ADR practice.

## Not applicable

- **Authentication, session management, access control (ASVS V6–V8).** Not
  claimed. `auth` is not in `requirements`, and `overview.md` says there is no
  sign-in; the one guard protects an unsaved draft, and `AGENTS.md` does not
  present it as access control.
- **OWASP API Security Top 10.** `project_type` is `web`, and the blueprint
  contains no API; the API is somebody else's and is replaced by
  `HttpTestingController` in tests.
- **CIS Docker Benchmark.** No container: `platforms` is `[web]` and the recipe
  builds static files.
- **WCAG 2.2.** `accessibility` is not claimed. The template accessibility lint
  rules, a skip link, `lang` per locale, labelled form controls and
  `aria-current` on navigation are present, but jsdom does no layout, so
  contrast and focus order are unverified — and `overview.md` says so rather
  than claiming the word.
- **OWASP LLM / Agentic / MCP references.** No model, no agent, no MCP server.
