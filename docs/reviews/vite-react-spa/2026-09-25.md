# vite-react-spa — architecture and security review

- Date: 2026-09-25
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22, WCAG rows
  2026-09-23 (next re-check due 2026-12-21)
- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Verdict: **MERGE**

## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
The catalog's first client-only application: React, React Router and Tailwind,
built by Vite into static files, with no server, no database and no server
rendering. Decision D14 of the 2026-09-24 expansion plan kept it apart from
`nextjs-fullstack-app` on exactly that line, and the similarity report agrees
(59% tags, 20% `AGENTS.md`, 33% `setup.md` against it).

The single most important thing a reader should know: **everything here is
public.** A client-only app has no place to keep a secret or enforce a
permission, and the blueprint says so first in `AGENTS.md` rather than leaving
it to be discovered. What it does well is turn its two boundaries —
configuration and the network — into lint rules and tests rather than
conventions.

The manifest claims `tier: community` and `provenance: generated`. No
`critical` or `high` findings are open.

## Findings

### 1. `accessibility` is claimed, and jsdom can verify only the structural part of it — `medium`

- **Where:** `blueprints/vite-react-spa/manifest.yaml:15` against
  `setup.md:653` (step 17) and `setup.md:847` (step 28)
- **Standard:** WCAG 2.2 — verified: 2.4.2 Page Titled (title asserted per
  route), 2.4.3 Focus Order (focus moved to `main` after navigation, asserted),
  2.4.1 Bypass Blocks (skip link), 4.1.2 Name, Role, Value and 1.3.1 Info and
  Relationships (axe-core on every route), 3.1.1 Language of Page (step 28
  greps the built `index.html`). Not verified: 1.4.3 Contrast (Minimum), 2.1.2
  No Keyboard Trap, 1.4.10 Reflow, 2.4.7 Focus Visible
- **What:** axe-core runs in jsdom, which does no layout. The test disables
  `color-contrast` by name, and nothing checks keyboard traps, reflow or
  whether the focus indicator is visible.
- **Why it matters:** `resolve` matches on `requirements`, and somebody asking
  for an accessible app is sent here on the strength of the word.
- **Mitigating, and why this is `medium` rather than `high`:** the gap is
  disclosed in the three places a reader looks — `AGENTS.md` ("It is not an
  audit"), `overview.md` under Cons and Trade-offs, and the comment above
  `axe.run` in the test itself — which is what `docs/review-standards.md`
  asks of a static check. Disabling contrast explicitly, rather than letting it
  come back "incomplete", is the right call: a green run cannot be misread as a
  contrast check. Two of the checks go further than the catalog's previous web
  blueprint: axe-core over the rendered DOM rather than regexes, and focus
  management, which is the accessibility failure specific to single-page apps.
- **Fix:** a browser-based suite (Playwright with axe) is the way to reach
  contrast and keyboard behaviour. It was left out on purpose because it
  downloads browsers from outside the npm registry, which the recipe rules do
  not allow; `overview.md` names it as the next step.

### 2. No Content-Security-Policy or other security headers — `low`

- **Where:** `blueprints/vite-react-spa/setup.md:95` (step 4, `index.html`)
- **Standard:** OWASP Top 10:2025 **A02 Security Misconfiguration**
- **What:** no CSP, no `frame-ancestors`, no `Referrer-Policy`.
- **Why it matters:** a CSP is the second line of defence against script
  injection, and `frame-ancestors` is the defence against clickjacking. React
  escapes rendered text and nothing here uses `dangerouslySetInnerHTML`, so the
  first line holds; the second is absent.
- **Mitigating:** these belong in response headers, which are the host's to
  set, and a meta-tag CSP cannot express `frame-ancestors` at all. The
  `connect-src` a CSP needs is the API origin, which is only known per
  deployment. `AGENTS.md` lists the omission under "What this does not do" and
  says where it belongs.
- **Fix:** none in the recipe. A host-specific header file would name a host,
  which the blueprint deliberately does not.

### 3. The CI build uses a placeholder API URL — `info`

- **Where:** `blueprints/vite-react-spa/setup.md:788` (step 19)
- **Standard:** The Twelve-Factor App **III. Config**
- **What:** `VITE_API_BASE_URL: https://example.com/api` in the workflow's build
  step, with a comment saying a deploy job sets the real value from a
  repository variable.
- **Why it matters:** the CI build proves the bundle builds, not that it points
  at a working API — correct for a check, and the reason the value is an
  RFC 2606 domain rather than something plausible. Recorded because the value
  is compiled into the bundle, and a reader who deploys the CI artefact would
  ship a front end that talks to nothing. There is no deploy job, and
  `overview.md` says so.

### 4. The API URL is fixed at build time — `info`

- **Where:** `blueprints/vite-react-spa/setup.md:487` (step 12)
- **Standard:** The Twelve-Factor App **V. Build, release, run**
- **What:** Vite compiles `VITE_` variables into the bundle, so one build
  serves one environment.
- **Why it matters:** Twelve-Factor wants one build promoted through
  environments. For a static bundle that means a runtime `config.json`, which
  costs a request before the first render. `overview.md` names the trade-off
  and the alternative. Not a defect; a decision recorded where somebody can
  disagree with it.

## What was checked and found sound

- **Configuration has one entry point and fails early** (Twelve-Factor III;
  OWASP Top 10:2025 A10). `readConfig` requires `VITE_API_BASE_URL`, requires
  it absolute, and requires https outside loopback — so mixed content and
  plaintext API traffic are refused at startup. `vite.config.ts` runs the same
  function at build time, and step 24 proves a build without the variable
  fails with that message and writes no `dist/`. The lint config refuses
  `import.meta.env` anywhere but `main.tsx`.
- **No secret can hide in configuration** (CLAUDE.md §5b; OWASP A02).
  `AGENTS.md` leads with the fact that a `VITE_` variable is published in the
  bundle, the config module repeats it, and `.gitignore` covers `.env*` before
  any environment file exists.
- **The network boundary is real** (OWASP Top 10:2025 A01 Broken Access Control,
  which absorbed SSRF). Only `src/api/` may call `fetch`, enforced
  by `no-restricted-globals`. Responses are `unknown` until a guard checks
  them, and a test proves a wrong shape is refused. `resolveApiUrl` refuses a
  path that resolves to another origin — the client-side request-forgery case
  that appears the moment a path is built from a URL parameter — and a test
  proves `//host` and absolute URLs are refused.
- **No ambient credentials cross origins.** `credentials: 'same-origin'`, with
  the reason beside it and the CORS decision it implies named in `AGENTS.md`.
- **Authorization is not pretended** (ASVS 5.0 access control chapter, by
  absence). `AGENTS.md` says hiding a route is presentation and the API
  decides; `auth` is not claimed.
- **Failures are handled and visible to the user** (OWASP A10). A failed loader
  renders an error page inside the layout with `role="alert"`, and a test
  proves the navigation survives it. Loaders get the router's abort signal, so
  a slow response cannot overwrite a page the user has left.
- **No source maps shipped.** `build.sourcemap: false`, step 26 proves none
  exist, and the generated CI fails if one appears.
- **Supply chain** (OWASP Top 10:2025 A03; SLSA v1.2; SSDF). Every direct
  dependency pinned to an exact version, checked against the npm registry on
  2026-09-24. The recipe writes `package-lock.json`, step 2 and `AGENTS.md`
  say it is committed, and the generated CI installs with `npm ci`.
  Actions are pinned by commit SHA (checkout v7.0.1, setup-node v7.0.0, both
  resolved through the GitHub API), `permissions: contents: read`, and
  `persist-credentials: false`. No end-of-life major: ESLint 9 reached end of
  life on 2026-08-06, and this uses 10.
- **The tests prove the claims.** Removing the focus call fails the focus test;
  removing a link's accessible name fails axe on every route. Both mutations
  were run.
- **No third-party scripts, fonts or analytics** reach the browser.
- **No secrets, no personal data, no employer information** (CLAUDE.md §5b).
  The only hosts named are `example.com`, `example.net` and `localhost`.

## Not applicable

- **Authentication, session management (ASVS 5.0).** Not claimed; there are no
  users, and `overview.md` lists sign-in under "What it is NOT for".
- **OWASP API Security Top 10.** The project consumes an API and contains none.
- **Rate limiting (API4:2023).** Belongs to the API.
- **CIS Docker.** No container.
- **OWASP LLM 2025 and Agentic 2026.** `project_type: web`, no model, no tools.
- **Migrations, multi-tenancy.** Not claimed, no database.
- **Observability (OWASP A09).** Not claimed; `AGENTS.md` states there is no
  error reporting and that a failed load is seen only by the user.

---

## Verdict

**MERGE.** One `medium`, one `low`, two `info`.

The `medium` is the same shape as `astro-content-site`'s: a requirement word
bigger than what a machine without a browser can verify, disclosed where a
reader looks. It is narrower here, because axe-core over a rendered DOM and an
asserted focus move cover more of WCAG 2.2 than static regexes do, and the
remaining gap is named by success criterion.

`tier: official` is not available while `provenance: generated` (ADR 0011).
`tier: verified` is available the day a maintainer runs the setup themselves.
