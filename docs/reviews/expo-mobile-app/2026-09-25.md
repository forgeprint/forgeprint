# expo-mobile-app — architecture and security review

- Date: 2026-09-25
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due
  2026-12-21). ASVS 5.0 requirement numbers were read from the OWASP/ASVS
  repository (`5.0/en`) on the day of this review.
- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Verdict: **MERGE**

## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
It is the catalog's first `mobile` blueprint: Expo SDK 57 on Expo Router,
scaffolded from Expo's default template and then given tests, a lint that
passes, an SDK dependency check, CI, and a build proof for web, Android and iOS
that needs no device or account.

The single most important thing to know before building on it: **the build
proof stops at JavaScript.** Hermes bundles for both platforms and a static web
export are produced and asserted; no native project is generated, compiled,
signed or run. `overview.md` says so under its own heading and lists the next
step for a device build, and that disclosure is what makes the `ci` and
`testing` claims honest rather than wide.

No `critical` or `high` findings. One `medium` is a transitive advisory in the
app bundle that the blueprint cannot fix and does disclose.

## Findings

### 1. A denial-of-service advisory in a runtime dependency of Expo Router — `medium`

- **Where:** `blueprints/expo-mobile-app/setup.md:22`, step 1 (the template's
  dependencies); disclosed at `blueprints/expo-mobile-app/overview.md:117`
- **Standard:** OWASP Top 10:2025 **A03 Software Supply Chain Failures**;
  OWASP ASVS 5.0 **15.2.1** (components within their remediation time frames)
- **What:** `expo-router` 57.0.23 depends on `query-string` 7.1.3, which
  depends on `decode-uri-component` 0.2.2, covered by GHSA-vcc3-ghjq-m6fr
  (exponential decoding of malformed percent-encoded input, published
  2026-08-31, fixed in 0.5.0). `npm audit --omit=dev` on the generated project
  reports 14 moderate findings from this root and from `uuid` (finding 2).
- **Why it matters:** this code is in the app bundle and parses URLs, and deep
  links are URLs a stranger can send. A crafted link could hang the app for the
  person who opened it.
- **Fix:** none is available inside the blueprint. 0.5.0 is ESM-only and
  `query-string` 7 loads it with `require`, so an `overrides` entry would break
  routing rather than fix it. Re-run `npm audit` on every SDK bump and drop the
  paragraph from `overview.md` when Expo Router moves off `query-string` 7.

### 2. `uuid` 7 in the build-time config tooling — `info`

- **Where:** `setup.md:22`, step 1: `expo-splash-screen` → `@expo/config-plugins`
  → `xcode` 3.0.1 → `uuid` 7.0.3
- **Standard:** OWASP Top 10:2025 **A03**
- **What:** GHSA-w5hq-g745-h8pq (missing bounds check when a caller passes its
  own buffer to v3/v5/v6). The package runs when native projects are generated,
  not in the app, and `xcode` does not pass a buffer.
- **Why it matters:** it inflates the audit count and nothing else.
- **Fix:** none. Recorded so the next reviewer does not re-derive it.

### 3. `.env` is not git-ignored, and build tools read it — `low`

- **Where:** the template's `.gitignore` (created by `setup.md:22`, step 1);
  described at `blueprints/expo-mobile-app/AGENTS.md:65`
- **Standard:** OWASP ASVS 5.0 **13.3.1** (backend secrets in a secrets
  management solution); CLAUDE.md §5b, mechanical protection
- **What:** the template ignores `.env*.local` and signing files but not
  `.env`. The Expo CLI loads `.env` into the environment of `app.config.js` and
  of build tooling, which is where a build-time token (an error-reporting
  upload key, for example) ends up.
- **Why it matters:** `AGENTS.md` correctly says nothing secret belongs in the
  app bundle, but a secret for the _build_ has no safe default location, and
  the one the tooling reads first is committable.
- **Fix:** a step appending `.env` to `.gitignore`, with the reason in a
  comment, and a sentence in `AGENTS.md` pointing build secrets at the CI
  secret store. Cheap; not blocking.

### 4. The web export ships Expo Router's `/_sitemap` and the template's samples — `low`

- **Where:** `setup.md:457`, step 24 (the export), and `setup.md:22`, step 1
- **Standard:** OWASP ASVS 5.0 **15.2.3** (production contains no sample
  snippets or development functionality)
- **What:** the static export writes `/_sitemap`, a page listing every route,
  and the template's `explore` screen with its example components.
- **Why it matters:** for this app the list is two routes and harmless. It
  stays harmless only while every route is meant to be public, and a reader
  adding an admin screen gets it listed by default.
- **Fix:** disclosed in `overview.md` (trade-offs). A later version can add
  `src/app/_sitemap.tsx` that redirects to `/`, and a sentence in `AGENTS.md`
  to remove the samples before the first release.

### 5. ESLint 9 is marked unsupported on npm — `low`

- **Where:** `setup.md:31`, step 4
- **Standard:** OWASP Top 10:2025 **A03**; ASVS 5.0 **15.2.1**
- **What:** `eslint@9.39.5` carries npm's deprecation notice. ESLint 10 is
  current, but `eslint-plugin-react` 7.37.5 and `eslint-plugin-import` 2.32.0,
  which `eslint-config-expo` 57 depends on, declare peer support up to ESLint 9.
- **Why it matters:** a development tool, not in the app, and it receives no
  fixes. Moving alone would put the configuration's own plugins out of range.
- **Fix:** none now; the CHANGELOG lists it under Planned. Recorded in
  `overview.md` as a trade-off.

### 6. Deep-link parameters are untrusted input — `info`

- **Where:** `app.json` `scheme` (template, step 1); rule at `AGENTS.md:71`
- **Standard:** OWASP ASVS 5.0 **2.2.1** and **2.2.2** (validate input; client
  validation is not a security control)
- **What:** every route can be opened from outside with parameters the sender
  chooses. No screen reads parameters today, and `AGENTS.md` makes validating
  `useLocalSearchParams()` a rule and a step in "Adding a screen".
- **Why it matters:** the first screen that takes an id will set the pattern.
- **Fix:** none required at this scope.

## What was checked and found sound

- **The scaffolder is pinned for real.** `create-expo` 5.0.2 is called directly
  because `create-expo-app` 5.0.0 depends on `create-expo >=5.0.1`, a range
  that would cross a major. The template is pinned to an exact version
  (57.0.27), not the moving `sdk-57` tag (OWASP Top 10:2025 A03).
- **The scaffolder does not write agent permissions.** Without
  `--no-agents-md`, `create-expo` 5 writes its own `AGENTS.md`, `CLAUDE.md` and
  `.claude/settings.json`: an agent permission file nobody reviewed, in a
  project an agent will then work in (OWASP Top 10 for LLM Applications 2025,
  excessive agency). The recipe passes the flag and says why.
- **The dependency check is deterministic and proves itself.** The check,
  `expo install --check` under `EXPO_OFFLINE=1`, compares against the table
  inside the installed `expo` package and exits non-zero on a mismatch; this was confirmed
  by downgrading `react-native-web` by hand before writing the step (A03).
- **Typed routes are a check, not a setting.** `typed-routes.test.ts` expects a
  non-existent path to be a compile error; with the generated types missing the
  directive goes unused and `tsc` fails. Confirmed both ways.
- **The tests prove the claims they make.** The rule is tested as a function;
  the screen is rendered through Expo Router's harness and driven by role and
  label, including the error path and a navigation. The web export's HTML is
  asserted to contain the home screen, which is only true if static rendering
  ran the route.
- **Boundaries.** `src/features/greeting` imports nothing from React or React
  Native; the route depends on it and not the reverse (Clean Architecture's
  dependency rule). `AGENTS.md` makes "only routes in `src/app`" a rule with
  its failure mode: a helper there becomes a URL.
- **Secrets in the bundle.** `AGENTS.md` states that every `EXPO_PUBLIC_*` value
  is inlined and readable by anyone with the app, and that secrets belong on a
  server (ASVS 5.0 13.3.1; Twelve-Factor III). No example value exists to leak.
- **CI workflow.** Actions pinned by commit SHA with the version beside it
  (both SHAs checked against the tags on 2026-09-25), `permissions: contents:
read`, `persist-credentials: false`, `npm ci` against the committed lockfile,
  no secrets referenced (SLSA v1.2; OWASP Top 10:2025 A03).
- **Telemetry is off wherever the recipe runs Expo.** `EXPO_NO_TELEMETRY=1` on
  every Expo command in `setup.md` and at the workflow level; `AGENTS.md` tells
  the reader to set it for local use. No standard on the list covers this; it
  is recorded as the behaviour, not graded.
- **Network.** Every step reaches only the npm registry. The one Expo command
  that would call Expo's servers, the dependency check, runs offline.
- **Nothing privileged, nothing global, one `rm` of one named file.**
- **No secrets, personal data or employer information** (CLAUDE.md §5b). The
  template's `LICENSE` names Expo as copyright holder; `README.md` in the
  generated project and `overview.md` both tell the reader to replace it, and
  the manifest records the derivation (ADR 0008).

## Not applicable

- **Authentication, session management, authorization (ASVS 5.0 V6–V10).** No
  users, no server, no tokens; `overview.md` says so under "What it is NOT for".
- **OWASP API Security Top 10.** No API.
- **OWASP LLM 2025 and Agentic 2026** beyond the scaffolder point above.
  `project_type: mobile`, no model.
- **CIS Docker.** No container.
- **WCAG 2.2.** `accessibility` is not claimed. The tests do query by role and
  label, which is a floor, not a claim; nothing here asserts contrast, focus
  order or screen-reader output on a device.
- **Transport security (ASVS 5.0 V12).** The app makes no network request.
- **OWASP Top 10:2025 A10.** The only failure path is invalid input, which is
  announced to the user and tested.
- **Native build, signing and store controls.** Not built, not tested, and
  disclosed as such; there is nothing to review until a native project exists.

---

## Verdict

**MERGE.** One `medium` that is disclosed and waits on Expo, two `low` with
cheap follow-ups, three `info`. The blueprint's claims are narrower than its
name might suggest and it says so plainly: what CI proves is that the
JavaScript is typed, linted, tested and compiles for all three platforms, and
`overview.md` names everything it does not prove.

`tier: official` is not available while `provenance: generated` (ADR 0011).
`tier: verified` is available the day a maintainer runs the setup and opens the
result on a phone.
