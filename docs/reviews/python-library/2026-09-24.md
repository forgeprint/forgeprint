# python-library — architecture and security review

- Date: 2026-09-24
- Blueprint version: 1.0.0
- Standards: `docs/review-standards.md` as checked 2026-09-22 (next re-check due
  2026-12-21)
- Reviewer: maintainer's Claude Code agent, `/arch-review`
- Verdict: **MERGE**

## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
The catalog's second `lib` and its first Python one: a typed library on uv
whose release publishes to PyPI from a tag through trusted publishing.

A pure-Python library has no runtime attack surface of its own — no network, no
storage, no requests — so, as with `ts-library`, this is mostly a supply-chain
review, plus one question about the example code, because the example is what
a reader copies. The strongest thing about it is that it checks the artefact
rather than the source tree: the wheel is opened, installed alone and
type-checked against, in the recipe.

The manifest claims `tier: community` and `provenance: generated`, and
`requirements: [testing, ci, cd]`. The review checks each of the three claims
against what the recipe actually proves.

## Findings

### 1. The arithmetic depends on the caller's decimal context — `low`

- **Where:** `blueprints/python-library/setup.md:121` and `:127` (step 2)
- **Standard:** OWASP Top 10:2025 **A10 Mishandling of Exceptional
  Conditions**
- **What:** `amount % quantum` and `amount / quantum` run in whatever
  `decimal` context the caller has active. With the default 28 digits, an
  amount of more than 28 significant digits in quanta raises
  `decimal.InvalidOperation`; with a caller that lowered the precision to 4,
  `split(Decimal("123.45"), 3)` raises the same. Both were run while writing
  this report.
- **Why it matters:** the failure is loud, not silent — the shares never come
  back wrong — but it is an exception type the docstring does not name, from
  a function whose contract is "raises `TypeError` or `ValueError`". A caller
  handling those two will not handle this one.
- **Fix:** do the arithmetic inside `decimal.localcontext()` with enough
  precision for the amount (its digit count plus the quantum's exponent), or
  in integers via `scaleb`, and add a test that runs `split` under a
  low-precision context. Not a blocker: nothing is wrong at the precisions
  money actually has.

### 2. Trusted publishing, but no PEP 740 attestation — `low`

- **Where:** `blueprints/python-library/setup.md:436` (step 11)
- **Standard:** SLSA v1.2, provenance; OWASP Top 10:2025 **A03 Software Supply
  Chain Failures**
- **What:** `uv publish --trusted-publishing always` authenticates to PyPI with
  a short-lived OIDC token, so no credential is stored. It uploads attestations
  when they exist beside the files (`uv publish --help` documents
  `--no-attestations`), but nothing in the workflow generates one.
- **Why it matters:** PyPI records that the release came from this workflow,
  which is most of the value. A PEP 740 attestation is the part a consumer can
  verify independently, and it is what `ts-library` gets from
  `npm publish --provenance`. The two blueprints make the same claim with
  different strength.
- **Fix:** publish with `pypa/gh-action-pypi-publish` pinned by commit SHA,
  which signs attestations by default, or generate them in the publish job
  before `uv publish`. Either way the `id-token: write` permission stays where
  it is. Recorded rather than changed, because swapping the publisher is its
  own decision and its own version.

### 3. A pushed tag publishes, and the tag is not protected — `info`

- **Where:** `blueprints/python-library/setup.md:380` (step 11, the `v*` tag
  trigger) and `blueprints/python-library/AGENTS.md`, "Before the first
  release"
- **Standard:** SLSA v1.2, source track; OWASP Top 10:2025 **A03**
- **What:** anybody with write access can push a `v*` tag, and the release
  runs. `AGENTS.md` tells the reader to create the `pypi` environment and says
  a required reviewer there makes a tag wait for a person.
- **Why it matters:** the environment reviewer is the control that matters,
  and it is a repository setting the blueprint can describe but not apply. A
  tag ruleset restricting who may create `v*` tags would close the other half.
- **Fix:** one sentence in `AGENTS.md` pointing at tag rulesets. Recorded
  rather than added, because it is a claim about a GitHub settings page that
  should be read before it is written down.

### 4. The publish job runs a third-party action while holding `id-token: write` — `info`

- **Where:** `blueprints/python-library/setup.md:433` (step 11)
- **Standard:** OWASP Top 10:2025 **A03**; NIST SSDF, protect the software
- **What:** `astral-sh/setup-uv` runs in the only job that can mint a PyPI
  token.
- **Why it matters:** any code in that job could request the token. The
  action is pinned by commit SHA with its version in a comment, which is the
  mitigation the catalog uses everywhere, and the job has no checkout and no
  other permission.
- **Fix:** none required. The alternative in finding 2 (the PyPA action)
  would replace it with a different third-party action in the same position.

## What was checked and found sound

- **`cd` is real, and least-privilege.** The workflow's top-level permissions
  are `{}`; the build job has `contents: read`; the publish job has only
  `id-token: write` and sits behind the `pypi` environment, which is what the
  trusted publisher is bound to. No PyPI token exists to leak (SLSA v1.2;
  OWASP A03).
- **The tag cannot disagree with the version.** The release compares
  `v$(uv version --short)` with the tag and fails before building. The tag
  reaches the shell through `env`, not by interpolation into the command, so
  a crafted ref name is a value rather than code. Step 26 proves the command
  the check depends on works.
- **Checkout does not persist credentials** in either workflow, so a later
  step cannot reuse the job token.
- **Actions pinned by commit SHA** with the version in a comment; each SHA was
  resolved from its tag on 2026-09-24.
- **Every development tool pinned with `==`, and a lockfile.** `uv lock` then
  `uv sync --locked` everywhere, and CI uses `--locked` so a stale lockfile
  fails instead of being rewritten. The `python-cli` review recorded the
  absence of a lockfile as `info`; this blueprint has one (SSDF; SLSA v1.2).
- **The build backend is pinned exactly** (`uv_build==0.12.18`) and the build
  runs with `--no-sources`, so the artefact is what a consumer's build would
  produce.
- **No interpreter arrives unasked.** `python-downloads = "manual"` stops uv
  fetching a Python from outside the package registry during a sync, which is
  also what keeps the recipe inside CLAUDE.md rule 20.
- **`testing` is real.** Strict mypy over `src` and `tests`, ruff, pytest with
  `filterwarnings = error`, `xfail_strict`, strict markers and config, branch
  coverage with a floor, and doctests — with a step that proves the doctest is
  collected, because a doctest that silently stops being collected is the
  usual way one dies.
- **What ships is asserted from the artefact.** The wheel's own file list is
  read for `py.typed`, and a parsed count asserts nothing ships outside the
  package and its metadata. The count is computed from the archive rather than
  grepped from tool output, so a change in a tool's output cannot turn it into
  a vacuous pass — the weakness the `ts-library` review found in its step 14.
- **The wheel is used the way a consumer uses it.** It is installed into a
  throwaway environment with nothing else in it, and the import is asserted to
  come from `site-packages`. The `src` layout is what makes that assertion
  possible.
- **The types reach a consumer.** A strict mypy run against the wheel alone
  must report the float argument — which it can only do if `py.typed` shipped.
  The step accepts exit code 1 and nothing else.
- **The public surface is pinned by a test**, and a second test fails if a
  public name appears in the package namespace without being in `__all__`.
- **The example validates its input at the boundary.** A `float`, a `bool`
  for `parts`, a non-finite amount, a non-positive quantum and an amount finer
  than the quantum are all refused, each with a test (ASVS 5.0, validation).
- **No runtime dependencies**, the smallest possible surface for a consumer.
- **No secrets, no personal data, no employer information** (CLAUDE.md §5b).
  The distribution name is `example-fairsplit`, and `AGENTS.md` says to rename
  it before the first publish.

## Outside this blueprint

Running the recipe showed that `forgeprint`'s option resolver collapses runs of
blank lines **inside fenced blocks** as well as outside them, so a Python file
written by a recipe gets one blank line between top-level definitions where
PEP 8 and every formatter want two. The recipe works around it by formatting
before it lints (step 15). The fix belongs in the tooling, in its own pull
request: the collapse should skip lines inside a fence.

## Not applicable

  no users, no requests.
- **OWASP API Security Top 10.** No API.
- **OWASP LLM 2025 and Agentic 2026.** `project_type: lib`; nothing is exposed
  to a model.
- **CIS Docker.** No container.
- **Rate limiting, caching, migrations, transport security.** Nothing opens a
  socket or stores anything.

## Verdict

**MERGE.** Two `low`, two `info`, nothing `critical` or `high`.

The one worth acting on first is finding 2: this blueprint and `ts-library`
make the same promise about publishing, and only one of them produces an
attestation a consumer can check.

`tier: official` is not available while `provenance: generated` (ADR 0011).
