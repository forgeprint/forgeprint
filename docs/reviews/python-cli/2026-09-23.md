## Findings

### 1. `typer.echo` writes to stdout with no separation of channels — `low`

- **Where:** `blueprints/python-cli/setup.md:118` (step 8)
- **Standard:** POSIX convention; OWASP ASVS 5.0, Error Handling — the same
  principle as not returning diagnostics in a success response
- **What:** the command writes its result to stdout, which is correct. What is
  absent is the other half: nothing here writes progress or diagnostics to
  stderr, because there is nothing to write yet.
- **Why it matters:** the first time somebody adds "Processing…" they will
  reach for `typer.echo`, it will land in stdout, and `tool > out.txt` will
  contain noise mixed with the answer. The example sets the pattern.
- **Fix:** `AGENTS.md` says exit codes are the API but does not say where
  progress goes. One sentence — `typer.echo(..., err=True)` for anything that
  is not the answer — would close it. Left open as a `low` because it is a
  documentation gap rather than a defect in what exists.

### 2. Arguments are typed but not otherwise validated — `low`

- **Where:** `blueprints/python-cli/setup.md:130` (step 8)
- **Standard:** OWASP ASVS 5.0, Validation chapter
- **What:** Typer enforces the annotation; `greet` then interpolates the value
  into a string. For this example there is nothing to exploit — no shell, no
  path, no query.
- **Why it matters:** identical to the finding in `node-cli`, and for the same
  reason: the next command takes a path or a URL, and the example is what the
  reader copies.
- **Fix:** none at this scope. Typer's own validators (`exists=True` on a
  `Path`, `min`/`max` on a number) are the right answer and belong in the
  command that needs them.

### 3. No dependency lockfile — `info`

- **Where:** `blueprints/python-cli/setup.md:22` (step 3)
- **Standard:** OWASP Top 10:2025 **A03 Software Supply Chain Failures**;
  SLSA v1.2
- **What:** direct dependencies pinned with `==`; transitive ones resolve at
  install time.
- **Why it matters:** the trade-off every blueprint here carries, recorded so
  the next reviewer does not raise it again.

## What was checked and found sound

- **The tests drive the real parser.** `CliRunner` invokes the command line —
  argument names, option spellings, exit codes. A test calling `greet()`
  directly would pass while `--shout` was misspelled in the command
  definition, which is the failure that actually happens.
- **A test asserts a bad invocation is non-zero**, so the exit code is treated
  as the interface rather than as an accident.
- **The callback is present from the first command**, which is the Typer trap
  this blueprint documents: with exactly one command Typer collapses it to the
  top level, and adding a second later silently changes the interface of the
  first. Caught while building this, and explained where it happens rather than
  in a footnote.
- **The recipe checks what a user sees**: runs the tool, reads the output,
  reads `--help` for the command name, asserts a bad invocation fails. Not "it
  imported".
- **Every version pinned with `==`**, including the development set, and CI
  installs from the same file the recipe does (SSDF; SLSA v1.2).
- **Actions pinned by commit SHA** with the version in a comment (A03).
- **The interpreter is resolved once** into a file rather than guessed at every
  step — the same fix `python-mcp-server` needed, carried forward rather than
  rediscovered.
- **No secrets, no personal data, no employer information** (CLAUDE.md §5b).

## Not applicable

- **Authentication, authorization, session management (ASVS 5.0).** No users,
  no server, no requests.
- **OWASP API Security Top 10.** No API.
- **OWASP LLM 2025 and Agentic 2026.** `project_type: cli`; no tools exposed to
  a model.
- **CIS Docker.** No container.
- **Rate limiting, caching, multi-tenancy, migrations, transport security.**
  None claimed, none implied, nothing opens a socket.

## Verdict

**MERGE.** Two `low` findings and one `info`, none blocking. Both `low`s are
about what the example teaches rather than what it does, which is the right
kind of finding for a blueprint — a reader copies the shape, and the shape is
sound.

The stdout/stderr one is worth acting on before this gets a second command,
and is recorded rather than fixed here so the change is its own decision.
