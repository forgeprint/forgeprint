## Summary

A generated blueprint, so the review is not optional (ADR 0011, CLAUDE.md §5c).
The catalog's first `mobile` blueprint in Kotlin and its first native Android
one: a single-module Jetpack Compose app on AGP 9.4.1 with a ViewModel exposing
`StateFlow`, a pure-Kotlin rule layer, JVM tests including the real screen
under Robolectric, lint as a gate, an unsigned R8 release build, and CI.

The most important thing to know before building on it: every test runs on the
JVM. Robolectric renders the real Compose code against a simulated framework,
which is strong evidence about the screen's logic and semantics and no
evidence about a device. `overview.md` says so under "What CI cannot prove".

The manifest claims `tier: community` and `provenance: generated`. No
`critical` or `high` finding is open.

## Findings

### 1. `testing` is proved on the JVM only; nothing runs on a device — `medium`

- **Where:** `blueprints/android-compose-app/setup.md:915` (step 26, the
  Robolectric screen test) and `:1068` (step 36); no `androidTest` source set
  exists
- **Standard:** OWASP MASTG v2.0.0 — its testing techniques for Android rely
  on dynamic analysis on a device or emulator; the review skill's rule that a
  claim wider than its verification is a finding
- **What:** `requirements: [testing]` is backed by 13 JVM tests. The screen
  test drives the real `TasksRoute` and ViewModel through
  `createComposeRule()` under Robolectric 4.17 at API 37, but on a simulated
  framework: no ART, no GPU, no IME, no manufacturer behaviour.
- **Why it matters:** `resolve` matches on the word. A reader expecting
  instrumented coverage gets JVM coverage.
- **Mitigating, and why this is `medium` rather than `high`:** the gap is
  disclosed where a reader looks — `overview.md:50` ("What CI cannot prove")
  names on-device behaviour, instrumented tests, visuals and the release build
  running, and "What you do next" says how to add instrumented tests. The
  tests that exist assert behaviour, not only compilation: a refused blank
  title, a toggled row, the remaining count, and the domain boundary.
- **Fix (when the app has device-only behaviour):** an `androidTest` source
  set run on Gradle Managed Devices. Recorded under "Planned" in the
  CHANGELOG.

### 2. No per-artifact checksum for dependencies; Robolectric fetches its runtime outside Gradle — `medium`

- **Where:** `blueprints/android-compose-app/setup.md:67` (step 3,
  repositories), `:1068` (step 36, first Robolectric run)
- **Standard:** OWASP Top 10:2025 **A03 Software Supply Chain Failures**;
  NIST SSDF v1.1 PS.3 (archive and protect each software release) via its
  integrity practices; SLSA v1.2 build track
- **What:** versions are pinned and repositories are restricted — Google's
  Maven repository only for `com.android`, `com.google` and `androidx` groups,
  `FAIL_ON_PROJECT_REPOS` — but there is no
  `gradle/verification-metadata.xml`, so an artifact is trusted on its
  coordinates and the repository's TLS. Robolectric's `android-all-instrumented`
  jar is downloaded from Maven Central at test time by Robolectric itself.
- **Why it matters:** a compromised artifact at a pinned coordinate would be
  accepted. The wrapper JAR and the Gradle distribution are checksummed; the
  libraries are not.
- **Mitigating:** disclosed in `overview.md` ("No Gradle dependency
  verification", "Robolectric downloads its Android runtime at test time")
  with the reason — AGP's `aapt2` is published per operating system, so
  metadata generated on one host refuses the build on another. Content
  filtering closes the dependency-confusion path between the two repositories.
  Dependabot (step 28) keeps pins moving, including security updates.
- **Fix (later):** generate verification metadata for every host OS the team
  builds on (`--write-verification-metadata sha256` on each), and commit it.

### 3. `minSdk` 26 admits platforms that no longer receive security patches — `low`

- **Where:** `blueprints/android-compose-app/setup.md:178` (step 7)
- **Standard:** OWASP MASVS **MASVS-CODE-1** — "The app requires an up-to-date
  platform version."
- **What:** the app installs on Android 8.0 and later.
- **Why it matters:** for an app that stores nothing and reaches no network,
  little. For the app this becomes — tokens, personal data — an unpatched
  platform undermines every storage and network control.
- **Mitigating:** the reason is stated in `overview.md:156`, and the app today
  holds no sensitive data.
- **Fix:** raise `minSdk` when the app starts handling sensitive data;
  MASVS-CODE-1 is the argument to cite.

### 4. `OldTargetApi` is off, so nothing warns when `targetSdk` falls behind — `low`

- **Where:** `blueprints/android-compose-app/setup.md:233` (step 7, `lint`)
- **Standard:** OWASP MASVS **MASVS-CODE-1**
- **What:** four lint checks that fail on the calendar rather than on the code
  are disabled, with the reason in a comment beside them. One of them,
  `OldTargetApi`, is the only automated signal that the target API is
  behind — and Dependabot does not move `targetSdk`.
- **Why it matters:** a stale `targetSdk` keeps older platform behaviour for
  the app and, after Play's yearly deadline, blocks updates.
- **Mitigating:** `AGENTS.md:107` states that nothing else will warn and what
  to do before 31 August each year. `targetSdk` is 37 today, above Play's 36.
- **Fix:** none needed now. If the reminder proves too easy to miss, a
  scheduled CI job that runs lint with `OldTargetApi` enabled as a warning.

### 5. R8 obfuscation is not a resilience control — `info`

- **Where:** `blueprints/android-compose-app/setup.md:189` (step 7)
- **Standard:** OWASP MASVS **MASVS-RESILIENCE-3** (anti-static analysis)
- **What:** R8 shrinks and renames; it does not claim to resist reverse
  engineering, and the blueprint does not claim `MASVS-RESILIENCE` either.
  `AGENTS.md` says nothing in an APK is secret. Recorded so nobody reads
  `isMinifyEnabled` as protection.

### 6. The CI cache is restored on pull requests — `info`

- **Where:** `blueprints/android-compose-app/setup.md:1021` (step 27,
  `cache: gradle`)
- **Standard:** SLSA v1.2 build track (what the build trusts)
- **What:** `setup-java` restores `~/.gradle` from GitHub's cache. GitHub
  scopes cache writes by branch, so a pull request cannot write a cache the
  default branch reads. Nothing to fix; recorded because a cache is an input.

## What was checked and found sound

- **Build integrity (A03, SLSA):** the Gradle distribution is downloaded,
  checked against Gradle's published SHA-256 (step 30) _before_ it is unpacked
  or run; the generated wrapper pins `distributionSha256Sum` (step 32); the
  wrapper JAR is checked against Gradle's published wrapper checksum (step 33);
  CI re-validates the JAR on every run with `gradle/actions/wrapper-validation`.
  During the dry run the wrapper refused a corrupted download with exactly this
  check, which is the control working rather than a defect.
- **Pinning:** every plugin and library version in the version catalog, the
  Compose libraries through one BOM, no dynamic versions; actions pinned by
  commit SHA, checked against their tags on 2026-09-25.
- **CI permissions (SSDF PO.3, SLSA):** `permissions: contents: read`,
  `persist-credentials: false`, a pinned runner image, a timeout.
- **Secrets (CLAUDE.md §5b, MASVS-STORAGE-1):** no signing configuration, no
  keystore, no password anywhere; `.gitignore` refuses `*.jks`, `*.keystore`,
  `*.p12` and `keystore.properties`; `AGENTS.md` sends signing to the
  environment of the machine that signs. Step 41 proves the release APK is
  unsigned.
- **Data leaving the device (MASVS-STORAGE-2):** backup is off on every API
  level — `allowBackup="false"` and `fullBackupContent="false"` below 31, and
  `data_extraction_rules.xml` excluding every domain from cloud backup and
  device transfer from 31 on. Lint enforced the second half: it refused
  `allowBackup` alone.
- **Least privilege (MASVS-PRIVACY-1, MASVS-PLATFORM-1):** no permission
  requested; step 43 proves the release APK carries only AndroidX Core's own
  signature-level receiver permission and is not debuggable. The only exported
  component is the launcher activity, which must be.
- **Network (MASVS-NETWORK-1):** the app has no network access and no
  `INTERNET` permission; at `targetSdk` 37 cleartext is refused by default, and
  `AGENTS.md` says not to re-enable it.
- **Input validation (MASVS-CODE-4):** the one untrusted input, a task title,
  goes through `checkTitle`: trimmed, not blank, bounded at 80 characters, with
  the limit tested on both sides.
- **Boundaries (Clean Architecture, hexagonal):** `domain/` imports nothing
  from Android, and `DomainBoundaryTest` fails the build if it does — and fails
  rather than passes if the package is empty. State has one writer, the
  ViewModel; the screen is split into a wired route and a stateless composable.
- **Error handling (A10):** the only failure the app has — a refused title —
  is a value (`TitleProblem`), shown to the user from a string resource, and
  tested. `update {}` is side-effect free, so a retried lambda cannot allocate
  a duplicate id.
- **Accessibility, as far as a test can assert it:** rows are one toggleable
  node with the checkbox role, and tests find nodes by visible text. The
  blueprint does not claim `accessibility`, so this is not scored.
- **Lint as a gate:** `warningsAsErrors` with no baseline; the four disabled
  checks are listed with the reason beside them. Two real issues were caught
  while building it — a `ViewModel` constructed inside composition and a
  plural written as a string — and fixed rather than suppressed.

## For the linter

`forgeprint lint-setup` reports `schemas.android.com` as a network host on
three lines of this recipe (steps 9, 14 and 15). It is the Android XML
namespace, `xmlns:android="http://schemas.android.com/apk/res/android"`, which
every Android manifest and resource with `android:` attributes must declare
verbatim; nothing is fetched from it. The rule that looks for hosts should
skip `xmlns` attribute values. That is a change to the linter, not to this
blueprint, and belongs in its own pull request.

`services.gradle.org` is reported on step 29; it is Gradle's distribution
host, which open pull request #87 adds to the allowed registries.
