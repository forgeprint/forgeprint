One command cuts a release now, and it is the first release cut by it.

## `forgeprint release <version>`

Cutting 0.2.5 by hand took six commands and produced three wrong diagnoses.
None of them were about the release; all of them were about reading npm's
output as though it meant what it said.

- `404 Not Found` on publish is a rejected token, not a missing package.
- `409 Cannot publish over previously staged version` is "this version already
  exists". It arrives _after_ a publish that worked, and nothing is staged
  ([npm/cli#9889](https://github.com/npm/cli/issues/9889)).
- `npm view --prefer-online` served the previous version for minutes after the
  package page showed the new one — which is what nearly turned a finished
  release into an attempt to skip a version number that was never stuck.

So the command is built on not believing the publish. It publishes one package
at a time, then asks the registry what happened, retries because the registry
lags, and treats an error as an error only if the registry agrees.

Around that are the checks a release should not be able to skip: a clean tree,
a pushed HEAD, every published package at the version with a changelog entry
for it, and CI green on the commit about to be tagged — tags are protected here
and releases are immutable, so a tag pointing at an unverified commit is the
one mistake that cannot be taken back.

The first run writes a draft of the notes from the changelogs and stops, so a
human rewrites them before anything immutable exists. Running it again after a
failure is safe: whatever is already done is skipped.

Without Actions it reports the CI state as unknown and lets the maintainer
decide, rather than refusing to work
([ADR 0002](../decisions/0002-actions-optional.md)). Two steps stay outside it,
because both reach someone else's registry and neither is reversible:
`mcp-publisher publish server.json`, and the [dogfood test](../dogfood.md). It
prints both when it finishes.

## Also

`docs/releasing.md` now leads with the command and keeps the manual steps
below it, for when the command is unavailable.

0.2.5 reached npm without a tag or a release; this is where the record picks up
again. Nothing in 0.2.5 is missing from the repository — the packages are
identical to what `v0.2.6` contains, minus this command.
