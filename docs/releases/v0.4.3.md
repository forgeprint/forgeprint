A release-tooling fix, and nothing an installed copy behaves differently for.
Everything the catalog serves is unchanged from
[0.4.2](https://github.com/forgeprint/forgeprint/blob/main/docs/releases/v0.4.2.md).

## An unreadable CI state was a note, and is now a question

`release` asks GitHub whether CI is green on the commit it is about to tag.
When `gh` could not answer, it printed

```
note   CI state unknown (gh could not reach GitHub); releasing on your own verification
```

and carried on. With `--yes` nothing stood between that line and the tag, so
`v0.4.1` was tagged while `setup-test` was still running. The note described
the situation correctly and nothing acted on it.

There are four answers now, and they are a decision rather than two states and
a sentence:

| CI                | What happens                                                            |
| ----------------- | ----------------------------------------------------------------------- |
| failed            | refused, as before                                                      |
| green             | proceeds                                                                |
| `--skip-ci`       | proceeds — passing the flag **is** the statement that you verified HEAD |
| could not be read | asks, and `--yes` is refused with the flag that answers it              |

Releasing without Actions stays possible, because
[ADR 0002](https://github.com/forgeprint/forgeprint/blob/main/docs/decisions/0002-actions-optional.md) says it must. It stops
being the default.

**`--yes` does not answer that question.** "Do not ask whether I meant it" is
a different statement from "a check that could not run counts as a check that
passed", and collapsing the two is the whole defect.

## Why the fix moved code

The old logic was three conditionals inside a function that shells out to
`git`, `gh`, `pnpm` and `npm`, so none of it could be tested. The decision is
now a pure function with four cases behind it — including the one that would
have caught this: an unreachable `gh` returns `unverified`, not `green`.

## Upgrading

Nothing to change, and nothing to hurry. This is the maintainer's release
path, not the server or the catalog: `npx -y forgeprint-mcp` and
`npm i -g forgeprint` pick it up whenever they next resolve.
