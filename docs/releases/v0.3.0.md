Everything since 0.2.5, which is still what npm serves. 0.2.6 through 0.2.10
were written, tagged and never published — the npm token had expired, and the
publish step failed silently every time. That is fixed, and this release is the
first one since 0.2.5 that actually reaches a registry.

**The catalog answers three questions now, not one.** That is the change worth
reading; everything else in these notes follows from it.

## Three questions, four kinds

A blueprint answers _what are you building_. Two more questions get asked in
the same breath and had no unit behind them ([ADR 0012](https://github.com/forgeprint/forgeprint/blob/main/docs/decisions/0012-experts-crews-integrations.md)):

| Kind            | The question                      | What it is                                                                                                                        |
| --------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **Expert**      | How should the agent work?        | A way of working, not a persona. It names what it produces, which checklists it applies, and which sourced references it rests on |
| **Integration** | With which tools?                 | A pinned, permission-documented install recipe for software somebody else publishes. Forgeprint hosts none of that code           |
| **Crew**        | Who belongs together on this job? | A named package of experts, under the contributor's byline. It composes and copies nothing                                        |

**Seven experts, two crews, ten integrations.** Five of the experts are
software — architecture, security review, data engineering, test automation,
platform engineering — and two are not: technical writing and product
management, chosen from evidence rather than taste ([the role research](https://github.com/forgeprint/forgeprint/blob/main/docs/research/2026-09-23-roles.md)
says what the evidence was, and which figure it deliberately does not rely on).

Every one of them is `tier: community` with `provenance: generated`. A tool
drafted them; `official` is a claim only a person can make, and the schema
enforces that. Each overview says the same thing: **if it changes nothing about
what your agent produces, say so in an issue.** That is the evidence a
generated entry most needs.

The ten integrations pin real versions read from the registry on the day they
were written, not recalled. One candidate was dropped on the way: `mcp-remote`
shows a maintainer other than the package's original author, and an
integration's whole claim is a verified upstream.

## Forgeprint is not a Claude Code product

Claude Code is the first client verified end to end. It is not the target
([ADR 0013](https://github.com/forgeprint/forgeprint/blob/main/docs/decisions/0013-agent-agnostic.md)).

`schema/agents.yaml` records nine agents — Claude Code, Cline, Codex CLI,
GitHub Copilot CLI, Cursor, Gemini CLI, Kiro, OpenCode, Windsurf — and every
field in it traces to the vendor's own documentation and the date it was read.
Nothing is written from memory, and a field nobody verified is `null` rather
than a guess. Entries expire after 90 days, as a warning rather than an error.

What that research found is why the file exists at all:

- Gemini CLI reads `GEMINI.md`; `AGENTS.md` works only once it is added to the
  `context.fileName` setting.
- Cursor **ignores** a `.cursor/rules` file with no frontmatter — not a weaker
  rule, skipped entirely.
- Windsurf truncates a workspace rule at 12,000 characters and says nothing.
- Claude Code reads `AGENTS.md` only when no `CLAUDE.md` sits at or above the
  working directory.

Content is written once, as `AGENTS.md` and `SKILL.md`. Agent-specific files
are **generated** by `forgeprint render --agent <id>`, which refuses past
Windsurf's cap rather than letting the context be half-delivered. A
hand-written per-agent copy is refused — that is the no-variants rule in a
second costume.

## Tools

### forgeprint

- **Three new manifest schemas**, each governed the way a blueprint is, plus
  what makes each one mean something: a checklist name must have a file behind
  it, a crew holds at most six members, an integration pins its upstream and
  keeps that pin separate from its own version.
- **`validate` extended** to all four kinds, their cross-references, and the
  agent registry against the vocabulary that derives from it. A recommendation
  pointing at nothing now fails — it breaks no build and costs the reader
  everything.
- **`similarity --expert`** applies the duplicate report to `SKILL.md` and the
  checklists.
- **`render --agent <id>`** writes one entry in the layout one agent reads.
- **`render-check`** renders every entry for every registered agent: 216
  renders across 24 entries and 9 layouts. It is the half of an agent matrix a
  machine can prove — a recipe is executed by this CLI, not by an agent, so
  running one "as Cursor" would demonstrate nothing.
- **`get <slug> --agent <id>`** is the path for agents with no MCP client,
  deliberately the same code as `render`.
- **`lint-integration`** holds an install command to a setup step's standards:
  no pipe into a shell, no privilege escalation, no moving tag, no literal
  credential, and no declared secret the command never passes.

### forgeprint-mcp

Four new tools, and a route rather than an answer.

- **`recommend_experts`** returns at most one crew **or** at most three
  experts, each with a reason, and says how many it left out. A crew wins only
  when the task is plainly the whole job it is assembled for.
- **`get_expert`**, **`get_crew`**, **`get_integration`** return the content
  plus the file paths the named agent reads. Where an agent has no verified
  install syntax, they say so and link its documentation rather than guessing a
  command.
- **`resolve` gains `intent`**, which **routes** rather than answers. This tool
  returns exactly one blueprint or nothing; handing back an expert would break
  that rule quietly, so a non-project intent comes back as "use this tool, pass
  this".

### The site

Four tabs with one panel open at a time, a page per expert, crew and
integration, and agent badges with two states and no third: tested or unknown.
`agents[]` means somebody verified it, and the state is carried by a mark and a
label rather than by colour alone.

The **53 roles with no expert behind them** are published as a section. That
list being long is the design: the vocabulary is deliberately wider than the
catalog so an empty role reads as a contribution call.

## Contributing

`expert-author` and `crew-author` join `blueprint-author` and
`blueprint-review`, installable the same way. `/review-pr` decides the kind
first and reviews each against its own rules, and integration review gained the
check no linter can do — open the upstream, confirm the project is the one
named, confirm the pin exists there.

A new small pull request type, **`agent-verification`**: you ran an existing
entry with an agent that was not on its list, and the whole review is whether
there is evidence.

## Upgrading

Nothing in the blueprint tools changed shape, and no manifest needs editing.
One thing to know if you set it:

- **`FORGEPRINT_FILES_URL`** now points at the repository root rather than at
  `blueprints/`, because reading a file needs a kind. The default is correct;
  only an override needs changing.
