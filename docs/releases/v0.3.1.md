A fix release, and the first one where a fix was measured before it shipped.

## An agent that knows the domain has to be told when to look

The 0.3.0 dogfood run looked like a pass. The agent built a multi-tenant
ASP.NET Core API, the isolation tests were green, and a Customers endpoint sat
correctly behind the query filter. The transcript said otherwise: 38 tool
calls, none of them Forgeprint's. The agent had built the whole thing from its
own knowledge.

The cause is a change in how agents load tools. Claude Code now lists MCP tools
by name among dozens of others and fetches a schema only if it decides to, so
the server instructions are the one piece of Forgeprint text read before that
decision. They said what Forgeprint does and not **when** to use it, and "I know
C#, I'm building a multi-tenant SaaS API" reads as a request to start coding.

**`forgeprint-mcp` now opens its instructions with the trigger**: when somebody
is about to start a new project, call `resolve` before writing code, creating
files or proposing a design of your own. `resolve`'s description starts the
same way.

Measured before release, and with the limits stated:

|                                          | reached `resolve`                                                                       |
| ---------------------------------------- | --------------------------------------------------------------------------------------- |
| 0.3.0, headless                          | 9 of 10 — the miss offered "schema per tenant" from its own knowledge                   |
| this release, headless                   | 10 of 10                                                                                |
| this release, interactive, clean session | found `resolve` unprompted, asked only the blueprint's options, stopped before building |

Weak evidence in both directions: headless runs mostly succeed without the
fix, and one interactive run is one run. Enough to ship a cheap change that
points the right way. The clean end-to-end run against this published version
is the next test, and [docs/dogfood.md](https://github.com/forgeprint/forgeprint/blob/main/docs/dogfood.md)
now checks that the project is the recipe's before it counts a pass.

## The recipe works end to end

The same day, an agent ran `dotnet-multitenant-saas-api` from the first step to
the last: 34 of 34 with every verification, and step 5 checked by hand —
`dotnet build` clean, `dotnet test` 7 of 7. Three places where a careful agent
could have stopped were fixed in the blueprint's 1.2.1. Catalog changes like
that one reach you without upgrading anything, because the server reads the
published index.

## Tools

### forgeprint

`release` learned from what publishing 0.3.0 took:

- **Two publish failures named instead of echoed.** A stage-only npm token —
  which `npm whoami` and `npm token list` report exactly like a working one —
  and a 2FA browser challenge inside a subprocess each get a message that says
  what to do.
- **The registry wait loop waits.** It used to ask five times with no pause;
  0.3.0 took about ninety seconds to become visible.
- **`server.json` and every `plugin.json` are in the version gate.** They had
  drifted eight releases behind npm, and the MCP Registry was serving 0.2.1 on
  the day 0.3.0 shipped.
- **`release` publishes to the MCP Registry** instead of printing a reminder,
  and names the two failures that cost the most time: `mcp-publisher` missing
  from the shell's PATH, and the organization-namespace 403.

### forgeprint-mcp

The trigger above. No tool changed shape.

## Also in the catalog since 0.3.0

These shipped with the site, not with this package:

- **`technical-program-manager`**, an expert for work split across several
  agents: decide whether to split before splitting, freeze interfaces first,
  and never let a worker mark its own work done
  ([ADR 0014](https://github.com/forgeprint/forgeprint/blob/main/docs/decisions/0014-crew-runtime-deferred.md)
  records why that is an expert and not a runtime).
- Six blueprints closed the findings their architecture reviews had left open:
  a route-table test in both HTTP services, the trust boundary of a Celery
  broker, where a human checkpoint goes in an agent, a pack check that reads
  JSON instead of grepping it, and a plan-only Terraform test.
