0.4.0's release, finished. Everything in
[the 0.4.0 notes](https://github.com/forgeprint/forgeprint/blob/main/docs/releases/v0.4.0.md) is in this version — the catalog
at 152 entries, the annotations, the per-language experts — because 0.4.0 was
tagged and never reached npm.

## Why there is no 0.4.0 on npm

The tag exists and the GitHub release exists. The publish step did not: npm
answered `ENEEDAUTH` and the job stopped.

The cause was in [the workflow](https://github.com/forgeprint/forgeprint/blob/main/.github/workflows/release.yml), not in the
trusted publisher on npmjs.com. `actions/setup-node`, when it is given a
`registry-url`, writes an `.npmrc` holding
`_authToken=${NODE_AUTH_TOKEN}` and points `NPM_CONFIG_USERCONFIG` at it.
Trusted publishing sets no `NODE_AUTH_TOKEN`, so npm found an auth token
already configured, sent that empty value, and never asked GitHub for an OIDC
token at all. `registry.npmjs.org` is npm's default; the field bought nothing
and cost the release.

The tag was left where it is. A moving tag is not a pin, and the fix changes
the package itself, so `v0.4.0` would have stopped describing what npm
serves — the same reasoning as 0.2.9 to 0.2.10, which failed the same way for
a different reason.

## What made it hard to see, and is fixed

- **A failed publish now prints what npm said**, above the advice, on every
  path. The classifier printed its conclusion and discarded the output, so the
  failure arrived as one sentence about trusted-publisher configuration with
  no status code behind it. That sentence was written to save somebody an
  afternoon and it cost one instead.
- **"No credentials" and "credentials refused" are separate outcomes.**
  `ENEEDAUTH` was classified alongside 404 and 401 and inherited their
  message, which describes a publisher that does not match. Under OIDC they
  need opposite repairs: `ENEEDAUTH` means the exchange was never attempted,
  a 404 that npmjs.com attempted it and said no.

[`docs/releasing.md`](https://github.com/forgeprint/forgeprint/blob/main/docs/releasing.md) now carries the `registry-url`
trap as the first thing to know before a trusted publish, since it is
invisible in the workflow and reads like a credentials problem.

## Upgrading

From 0.3.1, this is the 0.4.0 release under a different number; read those
notes. Nothing to change: `npx -y forgeprint-mcp` picks up the server and
`npm i -g forgeprint` the tooling.
