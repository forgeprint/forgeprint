0.4.0 and 0.4.1 were tagged and neither reached npm. This is the same release
with the reason found: npmjs.com had no trusted publisher registered for the
`forgeprint` package. Everything in
[the 0.4.0 notes](https://github.com/forgeprint/forgeprint/blob/main/docs/releases/v0.4.0.md) is in this version.

## The symptom pointed at the wrong half of the setup

npm reported:

```
npm error code ENEEDAUTH
npm error need auth This command requires you to be logged in to https://registry.npmjs.org/
```

Which reads as a credentials problem on the machine. One line above it, and
only at `--loglevel verbose`:

```
npm http fetch GET  .../idtoken/...?audience=npm%3Aregistry.npmjs.org 200
npm http fetch POST 404 https://registry.npmjs.org/-/npm/v1/oidc/token/exchange/package/forgeprint
npm verbose oidc Failed token exchange request with body message:
                 OIDC token exchange error - package not found
```

GitHub issued the token. The registry declined the exchange. That endpoint is
**per package**, so "package not found" against a package npm plainly serves
means no publisher is registered on _that_ package — and npm then falls
through to an unauthenticated publish, which is where the login error comes
from.

## What is fixed, so the next one says it the first time

- **The case is named.** `publish --trusted` reports a missing trusted
  publisher as a missing trusted publisher, and says that it is configured per
  package rather than per organization.
- **`npm publish` runs at `--loglevel verbose`** on that path, because the
  line that says why is not printed at the default level.
- **A failed publish prints npm's own output** (0.4.1), and `ENEEDAUTH` is no
  longer classified with 404 and 401 (0.4.1).
- **`oidc-check`**, a `workflow_dispatch` job that reports the publish
  environment and rehearses the exchange against a version npmjs.com already
  serves — which cannot be published over, so it proves the exchange without
  publishing anything or spending a version number. It is what found this.

## What it cost, written down

Two version numbers, on two hypotheses, because the only way to test a
tag-triggered workflow was to tag. The rehearsal that settled it in one minute
should have been the first move after the first failure, not the fourth.

## Upgrading

From 0.3.1, this is the 0.4.0 release under a different number; read those
notes. Nothing to change: `npx -y forgeprint-mcp` picks up the server and
`npm i -g forgeprint` the tooling.
