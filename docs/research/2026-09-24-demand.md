# What the catalog should hold next — demand, 2026-09-24

A second round, one day after [2026-09-23](2026-09-23-demand.md), with a
narrower question: which **stack + project_type + requirements** combinations
are most used or most wanted by people starting new projects in 2025–2026,
especially with coding agents, and which of them the catalog does not hold yet.
Every row carries where its number came from and when it was read.

**What this is not.** It is not a plan and it authorises no blueprint
(CLAUDE.md §10, "Never invent a blueprint on your own"). It is evidence for the
maintainer to argue a plan against.

## How the numbers were taken

| Packagist downloads  | `packagist.org/packages/<vendor>/<pkg>/stats.json` (monthly)                        | read 2026-09-24                      |
| pub.dev downloads    | `pub.dev/api/packages/<name>/score` (`downloadCount30Days`)                         | read 2026-09-24                      |

| NuGet downloads      | `azuresearch-usnc.nuget.org/query?q=packageid:<pkg>` (all-time total)               | read 2026-09-24                      |
| GitHub stars         | GitHub REST API, `repos/<owner>/<repo>`                                             | read 2026-09-24                      |
| Surveys              | cited per row with the survey's own year; SO = Stack Overflow 2025, all respondents | read 2026-09-24                      |
| Builder defaults     | the builder's own documentation page                                                | read 2026-09-24                      |

Download counts measure installs, not developers: CI reinstalls, and a
transitive dependency counts the same as a chosen one. Stars measure attention,
not use. Maven Central and the Go module proxy publish no download counts, so
Java and Go rows lean on surveys.

**Where downloads and surveys disagree** (read these rows with care):

| Signal                     | Downloads                            | Survey / other                                     | Likely reason                                                                               |
| -------------------------- | ------------------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------- |

| Flask vs Django            | `flask` 29.8M/wk vs `django` 9.6M/wk | SO Flask 14.4% vs Django 12.6% — close, not 3 to 1 | Flask pulled in by ML and tooling packages                                                  |
| TanStack Start             | `@tanstack/react-start` 12.7M/wk     | State of JS 2025: 235 "other" mentions             | Lovable made it the default for new apps on 2026-05-13; generated projects inflate installs |

## What this round deliberately did not do

- **Did not verify survey chart percentages.** Where a figure lives only in a
  chart, it is listed under "Not fetched" instead of being estimated.
- **Did not count stars as usage.** Stars appear beside download or survey
  numbers, never alone as the reason for a rank.
- **Did not treat a builder's default as developer demand.** Lovable's and
  v0's defaults say what generated projects start with, which is why TanStack
  Start's downloads are flagged rather than taken at face value.
- **Did not add downloads across ecosystems.** A PyPI week, a crates.io
  90-day window and a RubyGems all-time total are not comparable; the rank is a
  judgment across signals, not a sum.
- **Did not run any recipe.** "CI-testable" says whether the recipe could run
  on a plain Linux runner, based on what each tool needs. Nobody has run one yet.
- **Did not propose a blueprint.** Choosing one is the maintainer's call
  (CLAUDE.md §10).
