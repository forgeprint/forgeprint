# Which crews next — team shapes, 2026-09-24

_Run 2026-09-24. Companion to [the role research](2026-09-23-roles.md), which
covers experts. This one covers crews._

A crew is a named package of experts and integrations, composed by slug, at
most six members, with `for_what` and `not_for` both required (ADR 0012).
Forgeprint has no multi-agent runtime (ADR 0014): a crew says which experts and
tools to load for a job, not how to run them. Two crews exist,
`api-hardening-crew` and `saas-launch-crew`. The question this report answers
is **which team shapes people already use with coding agents**, and which of
them are worth a crew once the evidence on multi-agent systems is taken into
account. Not which teams sound complete.

## How the evidence was taken

- **Stars** come from the GitHub REST API (`/repos/<owner>/<repo>`), read
  2026-09-24. The unauthenticated endpoint rate-limited partway through; the
  rest were read with an authenticated client against the same endpoint.
- **Team membership** comes from each project's own files: agent and skill
  directory listings, preset definitions and READMEs, read the same day. A
  shape counts as shipped when a project ships the roles together, as a preset,
  a workflow, a plugin or a documented example, not when the roles merely sit
  in the same list.
- **Downloads** come from the trending data the `claude-code-templates` project
  publishes in its repository (`lastUpdated` 2026-09-24T03:04Z). It lists the
  top ten agents and top ten MCP servers only.
- **Multi-agent evidence** comes from the primary sources named in its section:
  the post, paper or documentation page itself.
- A number that could not be fetched is listed under "Not fetched" and is not
  used anywhere in this report.

### The rules it implies

1. **Three or four members by default.** Six stays the limit; nothing above
   argues for reaching it.
2. **A checking role in every crew** — `qa-automation-lead`,
   `security-reviewer`, or a reviewer by another name. Verification is a fifth
   of the failures MAST found and the largest single fix it measured.
3. **`not_for` names sequential, small and same-file work** wherever it
   applies. Those are the jobs where more agents measurably do worse.
4. **A crew is worse than one agent** for strictly sequential reasoning, for
   tightly coupled edits to the same code, and for routine work where the
   token cost is never paid back.
5. **"N identical investigators" is not a crew.** The competing-hypotheses
   pattern runs one expert several times; that belongs in the expert's
   `SKILL.md`, not in a crew of distinct members.

## Decision recorded: the architect slot is filled per language

The architect slot appears in five crews, and the only expert that can fill it
today is `dotnet-senior-architect`, which holds the rule 9 triple
`software-architect / software / senior`. A second architect for another stack
would collide with it.

**Decision (maintainer):** per-language experts such as
`dotnet-senior-architect` are allowed. The architect slot in a crew is filled
by a language-specific architect, one per language, after an ADR widens rule 9
so that two architects for different languages are not a duplicate. Until that
ADR lands, crews 1, 2, 3, 7 and 10 can only name `dotnet-senior-architect`,
which makes each of them a .NET crew. The widening is the ADR's to define;
this report only records that it is the route taken, instead of a
stack-agnostic architect.

## What this round deliberately did not do

- **Write any crew.** This is the evidence. Each crew above still needs its own
  pull request, members that exist, and the rule 9 check for crews (one crew
  per member-and-integration set).
- **Rank by how complete a team looks.** A six-member crew that covers every
  angle is the "catalog with a title" the schema's `not_for` requirement is
  there to prevent.
- **Propose a runtime.** Shape E and the full-stack squad are the cases
  Scenario D exists to measure. ADR 0014 stays as it is until that result, an
  issue trail, or demand says otherwise.
- **Add integrations whose upstream is archived.** PagerDuty's and Semgrep's
  MCP repositories are both archived; neither is proposed.
- **Treat downloads as demand for a crew.** The download counts measure single
  agents and MCP servers. They say which roles people install, not which roles
  people install together. The shapes come from the projects that ship them
  together.
