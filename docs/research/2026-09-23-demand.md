# What the catalog should hold next — demand, 2026-09-23

Run with `skills/catalog-research`. Every row carries where its number came
from and when it was read. A row without one does not belong here: six months
from now nobody remembers which figures were measured and which were somebody's
impression.

**What this is not.** It is not a plan. It is the evidence a plan gets argued
against, and the candidates it produces are in
[catalog-candidates.md](../catalog-candidates.md). Nothing here authorises
writing a blueprint (CLAUDE.md §10, "Never invent a blueprint on your own").

## How the numbers were taken

| Kind                   | How                                                                   |
| ---------------------- | --------------------------------------------------------------------- |
| npm weekly downloads   | `api.npmjs.org/downloads/point/last-week/<pkg>`, week 2026-09-15..21  |
| PyPI monthly downloads | `pypistats.org/api/packages/<pkg>/recent`, read 2026-09-23            |
| NuGet total downloads  | `azuresearch-usnc.nuget.org/query?q=packageid:<pkg>`, read 2026-09-23 |
| GitHub stars           | `api.github.com/repos/<owner>/<repo>`, read 2026-09-23                |
| Surveys                | cited inline, with the survey's own year                              |

Download counts measure installs, not developers: CI re-installs the same
package every run, and a package pulled in as a dependency of something else
counts the same as one somebody chose. They are a floor on attention, not a
population. Survey percentages measure people who answered a survey. Neither is
a market; both are the best available, and they disagree often enough to be
worth reading together.

**What the surveys say that the download counts do not.**

- TypeScript passed Python as the most-used language on GitHub in August 2025,
  2.63M active users, +66% year on year ([Octoverse 2025][octoverse]).
- PostgreSQL is at 58.2% and leads the second database by about 15 points; it
  tops both most-admired and most-desired ([Stack Overflow 2025][so2025]).
  Every blueprint the catalog adds with a database should have a reason not to
  pick Postgres.
- FastAPI rose about 5 points year on year, the largest move among web
  frameworks in that survey ([Stack Overflow 2025][so2025]).
- Next.js keeps gaining usage while losing satisfaction ([State of JS
  2025][sojs2025]). Worth knowing before building a blueprint on it: usage is
  the reason to, satisfaction is the reason a reader may resent it.

**Where the catalog already is.** Rows 5, 8 and 9 are `dotnet-web-api` /
`dotnet-multitenant-saas-api`, `ts-mcp-server` and `dotnet-mcp-server`. Row 2
is `fastapi-service`, which carries `fastapi` and `postgres` but not
SQLAlchemy as a declared part of the stack. So of the fifteen strongest
combinations, four are covered and eleven are not — and the two emptiest
`project_type` values, `mobile` and `cli`, do not appear in the catalog at all.

## b) MCP servers and Claude Code plugins

Ordered by installs where a number exists. A caution first: **a directory's
server count is not an install count.** Published comparisons of Glama,
Smithery, PulseMCP and mcp.so quote index sizes from roughly 17k to 50k+
servers ([registry comparison][registries], July 2026), and those figures
measure how many servers each directory has indexed, not how many anybody
runs. Where a server ships on npm, the npm count is the honest number, so that
is the column below.

Not on npm and therefore not directly measurable here, but consistently near
the top of every directory's own ranking: **Browser Use** (115.9k stars),
**Supabase MCP**, and the official **Postgres** reference server. `browser-use`
is a Python library rather than a server anybody installs per project, which is
why its star count overstates its relevance to a blueprint.

**What this means for `provides.mcp`.** The reference servers (rows 4, 6, 8, 9)
are general: recommending them in a blueprint says nothing a reader could not
have guessed, and every blueprint recommending the same four is noise. The ones
worth naming in a manifest are the ones tied to what the blueprint _is_ —
Playwright for something with a browser, `server-everything` for an MCP server
blueprint, Sentry where the blueprint already sets up observability.

## Reading this again

This is due monthly (CLAUDE.md §6). The numbers move; the shape of the question
does not. What to watch next time:

- Whether `hono` closes on `express`, which would make row 4 a different
  blueprint than it is today.
- Whether the Python MCP SDK keeps pace with the TypeScript one. Row 3 is the
  clearest gap in the catalog right now.
- Whether any `blueprint-request` issue arrives. One person asking outranks
  every row above, because it is a person who can be answered.
