# Changelog

## 1.0.0 — 2026-10-08

A Flutter crew, which the catalog documented the absence of before it existed:
`mobile-app-crew` is React Native and its `not_for` names Flutter.

- Four members: `dart-senior-architect`, `flutter-mobile-engineer`,
  `accessibility-specialist`, `qa-automation-lead`. One mobile expert per stack
  is D21 of the [expansion plan](../../docs/research/2026-09-24-expansion-plan.md);
  this crew picks Flutter and adds the architect, because package boundaries in
  a pub workspace are decided before the first widget and nothing else in the
  catalog asks for them.
- No release manager, unlike `mobile-app-crew`: `not_for` points at
  `release-crew` instead. The member set therefore differs from the React
  Native crew in two places rather than one, which is what rule 9 asks of a
  second crew.
- One integration: `mobile-mcp`, for the device the audit and the journeys need.
- The README names the three places the members disagree, each from their own
  checklists, and keeps the accessibility specialist's stated limit: its method
  is written for the web.
- `tier: community`, `provenance: generated` (ADR 0011).
