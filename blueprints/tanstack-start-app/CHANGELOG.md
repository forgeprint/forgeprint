# Changelog — tanstack-start-app

## 1.0.0 — 2026-09-25

First version.

TanStack Start 1.168 on Vite 8 with React 19.3, TanStack Router 1.170
file-based routes, Zod 4 for search params, path params and server-function
input, Tailwind 4, a Nitro 3 Node server, and Vitest 5 for unit and e2e tests.

**Drafted by a tool** from
[the 2026-09-24 expansion plan](../../docs/research/2026-09-24-expansion-plan.md),
Phase 6, on the strength of the demand report: `@tanstack/react-start` 12.7M
installs a week (likely inflated by generated projects), the default for new
apps in one AI app builder since 2026-05-13, and the most-mentioned "other"
meta-framework in State of JS 2025. Its recipe runs in CI like every other and
nobody has built an application on it, so it is `tier: community` and
`provenance: generated`, and says so wherever it is served
([ADR 0011](../../docs/decisions/0011-generated-blueprints.md)).

What was verified, and on what: the recipe was run end to end by
`forgeprint test-setup` on Windows with Git Bash and Node 22.12.0 (49 steps,
about two minutes), and runs on Linux with Node 22 in the `setup-test` workflow.
Every version was read from the npm registry on 2026-09-25. `npm audit` reported
no known vulnerabilities in the production dependencies on that date.

Decisions that came out of building it rather than describing it:

**The scaffolder is `@tanstack/cli`, with its telemetry off.** `create-start`
now prints a deprecation notice pointing at it. The CLI sends usage events to
Google Analytics by default and writes an identifier under the home directory;
`TANSTACK_CLI_TELEMETRY_DISABLED=1` stops both. It writes `latest` for the
TanStack packages, so `package.json` is replaced with exact versions.

**Sign-in is a plain form post to the server function.** It works before
hydration, and it is what lets the e2e suite prove sign-in against the built
server with nothing but `fetch`.

**A validation failure is a thrown `Response` with status 400.** A thrown
`Error` from a validator comes back as a 500, and setting the status before
throwing is ignored on the form-post path.

**Configuration is checked when the server loads.** Without it, a server with
the development secret served public pages normally and failed only at
`/dashboard`, and the error never reached its log.

**The route tree is generated by the Start plugin, not the router CLI.** The two
generators disagree about the Start type registration at the bottom of the
file, so the router CLI and its config are removed and `dev`/`build` own it.

**A path parameter that does not parse throws `notFound()`.** Letting the
validation error escape made `/notes/abc` a 500.

**Sign-in is rate-limited, and the limit is checked before the password.** The
first draft had no limit; the architecture review raised it against the `auth`
claim, and scrypt makes an unlimited sign-in endpoint a way to spend the
server's CPU as well as a way to guess.

**Security headers are set in the server entry.** Also raised by the review:
the sign-in page could be framed. The policy forbids framing, `<base>`,
off-site form targets and plugins, and says plainly that it does not restrict
scripts.

**`vitest` is also pinned under `overrides`.** From Vitest 5.0.2's release on
2026-09-25, npm 10 and 11 crashed with "reading 'edgesOut'" on the pinned
5.0.1: an optional peer chain through `@vitejs/devtools` accepts any `vitest`
and npm resolved it to the newest. Nothing in that chain is installed.

### Planned

- A nonce-based script policy. Start accepts a nonce per request; proving that
  every inline script carries it needs a browser, which the recipe does not
  download.
- A rate limit that survives restarts and spans instances.
